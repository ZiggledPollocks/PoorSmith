These Editor-only fixtures live outside Assets and are not shipped. Copy only the required fixture into the approved isolated project's Editor validation folder. Never run against ordinary saves. Require `PlayerSettings.companyName == BatterMapValidation`, a fresh owned save root, and a valid completed-story fixture. Set `UnityEditor.SessionState.SetString("PoorSmithReleaseQA.Output", absoluteFreshOutputDirectory)` and create that directory before Run. Do not copy Packages/ProjectSettings back to batterMap.

- ReleaseExitQA.Run: start Title/Continue and field, wait for exit-ready.txt. An external owned process opens only that QA save with FileShare.None, writes exit-lock-ready.flag, holds about18s, then releases and writes exit-unlocked.flag. Expected exit-live.json: still playing, prompt true, gold5432. Retry must produce exit-stopped.json with expectedFailurePrompt true and a valid save with gold5432. Baseline pre-fix stopped without the prompt; retain ordinary save hashes.
- ReleaseReturnTitleQA.Run: same sequence using return-ready.txt, return-lock-ready.flag, return-unlocked.flag. It clicks the actual settings Main Menu button, verifies the failure popup, retries, reaches Title and continues back into the field with the saved gold6543 and restored input. Expected return-title.json.passed=true.

Use fresh marker files for every run. Verify resolved paths stay beneath the isolated QA directory before opening a file exclusively. Do not lock a user's source/Release save. These tests prepare gold/state and use synthetic UI events; they are not native OS input or a natural gameplay completion.
