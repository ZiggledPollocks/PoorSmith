UNITY 코드베이스 1차 분석 — 상세판
==================================

분석 범위와 사용법
------------------
- Assets 아래 C# 167개 전체를 확인했다.
- 실제 게임 코드인 Assets/JinHo/Scripts 36개는 주요 변수와 주요 함수의 조건 → 처리 → 상태 변화 → 결과를 상세히 설명한다.
- Cainos 97개와 TextMesh Pro 예제 34개는 외부 패키지다. 프로젝트 게임 흐름을 이해하는 데 필요한 수준으로 파일별 역할과 진입점, 상태, 연결, 확인점을 뒤쪽에 정리한다.
- Unity 6000.3.11f1, Cinemachine 3.1.7, Input System 1.19.0, 주 씬 Assets/Scenes/SampleScene.unity 기준이다.
- HIGH부터 읽고, 문제가 생긴 기능의 MEDIUM/LOW로 내려가면 된다.

2. HIGH — 입력, 이동, 도구, 상호작용
====================================

2.1 PlayerInputHandler.cs [HIGH]
--------------------------------

전체 역할
- Unity Input System의 PlayerInput 메시지와 장치 상태를 게임 로직용 상태로 바꾼다.
- 이동/점프/달리기는 PlayerMovement가 읽고, 공격 상태는 PlayerInteraction이 읽으며, 도구 선택은 직접 PlayerToolController에 전달한다.

주요 변수

MoveInput
- 수평 이동 입력을 -1~1로 저장한다. 이 게임은 Y 이동 입력을 버리고 X만 사용한다.
- PlayerMovement가 매 물리 프레임 목표 수평 속도를 계산하려면 필요하다.
- OnMove()가 변경하고 PlayerMovement.HandleMovement/HandleFlameMovement/HandleUpDraftMovement가 읽는다.

IsRunning
- 달리기 버튼이 현재 눌렸는지 저장한다.
- walkSpeed와 runSpeed 중 무엇을 쓸지 결정한다.
- OnSprint()와 Update()가 변경하고 PlayerMovement가 읽는다.

JumpPressed / JumpHeld
- JumpPressed는 한 번의 점프 요청, JumpHeld는 계속 누르는 상태다.
- 점프 버퍼와 짧은 점프, Flame 내부 상승을 서로 구분하기 위해 둘 다 필요하다.
- OnJump()/Update()가 설정하고 ConsumeJumpInput()이 JumpPressed를 지운다. PlayerMovement가 읽는다.

InventoryTogglePressed
- 인벤토리 토글 요청을 소비될 때까지 저장한다.
- 입력 콜백과 UI Update 실행 순서가 달라도 한 번의 입력을 잃지 않기 위해 필요하다.
- OnInventory()가 설정하고 ConsumeInventoryToggleInput()이 반환 후 초기화한다.

IsLeftClickHeld / LeftClickPressedThisFrame / LeftClickReleasedThisFrame
- 공격 버튼의 유지, 시작, 종료 상태를 저장한다.
- 자원 홀드 상호작용과 빠른 상호작용을 구분한다.
- OnAttack()이 변경하고 PlayerInteraction.Update()가 읽은 뒤 ConsumeAttackInput()이 프레임 플래그를 지운다.

wasLeftClickPressed
- 직전 공격 버튼 상태를 저장한다.
- 현재 입력과 비교해 pressed/released 전이를 만들기 위해 필요하다.
- OnAttack()과 OnDisable()에서 변경된다.

playerInput / sprintAction / jumpAction
- PlayerInput 컴포넌트와 Player/Sprint, Player/Jump 액션 참조를 저장한다.
- 메시지 콜백 외에도 Update에서 유지 상태와 WasPressedThisFrame을 안정적으로 읽는 데 필요하다.
- Awake/Start/CacheInputActions()에서 설정되고 Update()가 사용한다.

toolController
- 현재 도구 슬롯을 관리하는 PlayerToolController 참조다.
- 휠과 숫자 슬롯 입력을 실제 선택 상태 변경으로 연결한다.
- Inspector 또는 Awake()에서 설정하고 Update()/OnToolSlot0~2()가 사용한다.

주요 함수

Awake()

역할:
- 같은 GameObject의 입력/도구 컴포넌트를 확보하고 액션을 캐시한다.

호출 시점:
- Unity가 오브젝트 활성화 초기 단계에 1회 호출한다.

동작 방식:
1. GetComponent<PlayerInput>()으로 입력 컴포넌트를 찾는다.
2. toolController가 비어 있으면 같은 오브젝트에서 찾는다.
3. CacheInputActions()로 Sprint/Jump 액션을 검색한다.
4. 이후 Update와 입력 메시지가 사용할 참조가 준비된다.

사용/변경 변수: playerInput, toolController, sprintAction, jumpAction
연결 코드: PlayerInput, PlayerToolController, CacheInputActions()

Start()

역할:
- 현재 InputActionMap이 없으면 Player 맵으로 전환하고 액션을 다시 캐시한다.

호출 시점:
- 모든 Awake 이후 첫 프레임 전 Unity가 호출한다.

동작 방식:
1. playerInput과 currentActionMap을 확인한다.
2. 맵이 없을 때만 SwitchCurrentActionMap("Player")를 호출한다.
3. 맵 전환 뒤 CacheInputActions()를 다시 실행한다.
4. 결과적으로 Player 액션이 활성 맵에서 읽힌다.

사용/변경 변수: playerInput, sprintAction, jumpAction
연결 코드: PlayerInput.SwitchCurrentActionMap(), CacheInputActions()

Update()

역할:
- 달리기/점프 유지 상태를 폴링하고 마우스 휠 도구 전환을 처리한다.

호출 시점:
- 활성 상태에서 매 렌더 프레임 Unity가 호출한다.

동작 방식:
1. sprintAction이 있으면 IsPressed()로 IsRunning을 갱신한다.
2. jumpAction이 있으면 JumpHeld를 갱신하고, 이번 프레임 눌렸다면 JumpPressed=true로 만든다.
3. toolController 또는 Mouse.current가 없으면 도구 전환을 건너뛴다.
4. 휠 Y가 양수면 SelectNextTool(), 음수면 SelectPreviousTool()을 호출한다.
5. 결과적으로 Movement가 최신 입력을 쓰고 현재 도구가 바뀐다.

사용/변경 변수: IsRunning, JumpHeld, JumpPressed, toolController
연결 코드: InputAction, Mouse.current, PlayerToolController.SelectNextTool/SelectPreviousTool()

OnMove(InputValue)

역할:
- 2D 입력을 이 게임의 수평 입력으로 변환한다.

호출 시점:
- PlayerInput이 Move 액션 메시지를 보낼 때 호출한다.

동작 방식:
1. Vector2 입력을 읽고 X를 -1~1로 제한한다.
2. X와 Y가 동시에 유효하면 대각선 정규화로 작아진 X를 부호값 ±1로 복원한다.
3. Y는 0으로 버리고 MoveInput을 변경한다.
4. 다음 PlayerMovement 물리 프레임부터 수평 속도가 달라진다.

사용/변경 변수: MoveInput
연결 코드: PlayerInput, PlayerMovement

OnSprint(InputValue) / OnJump(InputValue)

역할:
- 버튼 콜백에서 달리기와 점프 상태를 기록한다.

호출 시점:
- PlayerInput의 Sprint/Jump 액션 메시지.

동작 방식:
1. isPressed를 확인한다.
2. Sprint는 IsRunning을 그대로 바꾼다.
3. Jump는 JumpHeld를 바꾸고 눌림 순간 JumpPressed=true로 만든다.
4. PlayerMovement가 속도 선택/점프 버퍼/점프 컷에 사용한다.

사용/변경 변수: IsRunning, JumpHeld, JumpPressed
연결 코드: PlayerMovement.UpdateJumpTimers(), PlayerMovement.ApplyJumpGravity()

OnAttack(InputValue)

역할:
- 공격 버튼의 눌림/유지/해제 전이를 만든다.

호출 시점:
- PlayerInput의 Attack 액션 메시지.

동작 방식:
1. 현재 isPressed와 wasLeftClickPressed를 비교한다.
2. 새로 눌렀으면 PressedThisFrame, 새로 놓았으면 ReleasedThisFrame을 true로 만든다.
3. Held와 이전 상태를 갱신한다.
4. PlayerInteraction이 시작/홀드/취소를 선택한다.

사용/변경 변수: IsLeftClickHeld, LeftClickPressedThisFrame, LeftClickReleasedThisFrame, wasLeftClickPressed
연결 코드: PlayerInteraction.Update()

OnInventory() / ConsumeInventoryToggleInput()

역할:
- 인벤토리 요청을 저장하고 UI가 정확히 한 번 소비하게 한다.

호출 시점:
- OnInventory는 Input System 메시지, Consume은 InventoryUIController.Update().

동작 방식:
1. 눌림일 때만 InventoryTogglePressed=true.
2. Consume은 false면 아무것도 하지 않고 false 반환.
3. true면 상태를 false로 바꾸고 true 반환.
4. UI가 한 번만 열리거나 닫힌다.

사용/변경 변수: InventoryTogglePressed
연결 코드: InventoryUIController.Update()

ConsumeJumpInput() / ConsumeAttackInput()

역할:
- 소비가 끝난 1회성 플래그를 지운다.

호출 시점:
- 각각 PlayerMovement.UpdateJumpTimers(), PlayerInteraction.Update().

동작 방식:
1. 해당 pressed/released 플래그를 false로 만든다.
2. 다음 프레임에 같은 입력이 재실행되지 않는다.

사용/변경 변수: JumpPressed, LeftClickPressedThisFrame, LeftClickReleasedThisFrame
연결 코드: PlayerMovement, PlayerInteraction

OnToolSlot0/1/2(InputValue)

역할:
- 버튼이 눌렸을 때 고정 슬롯 0/1/2를 선택한다.

호출 시점:
- 각 ToolSlot 액션의 PlayerInput 메시지.

동작 방식:
1. value.isPressed인지 확인한다.
2. 눌림이면 toolController.SelectToolSlot(index)를 호출한다.
3. 성공하면 현재 도구와 슬롯이 변경된다.

사용/변경 변수: toolController
연결 코드: PlayerToolController.SelectToolSlot()

CacheInputActions()

역할:
- 문자열 경로로 Sprint와 Jump InputAction을 찾는다.

호출 시점:
- Awake와 Start.

동작 방식:
1. playerInput/actions null이면 종료한다.
2. Player/Sprint와 Player/Jump를 FindAction(..., false)로 검색한다.
3. 누락되면 참조는 null로 남고 해당 폴링 기능이 작동하지 않는다.

사용/변경 변수: sprintAction, jumpAction
연결 코드: InputActionAsset.FindAction()

OnDisable()

역할:
- 비활성화 시 모든 입력 상태를 중립으로 초기화한다.

호출 시점:
- 컴포넌트/GameObject 비활성 또는 파괴 전.

동작 방식:
1. 이동/버튼/프레임/이전 클릭 상태를 모두 0/false로 만든다.
2. 재활성화 시 눌림이 고착되는 것을 막는다.

버그 발생 시 먼저 확인
- PlayerInput Behavior=Send Messages, Actions asset, Default Map=Player.
- 액션 이름과 메서드 이름이 정확히 대응하는지.
- 게임패드 Previous/Next 액션은 코드에서 처리하지 않고 마우스 휠만 직접 읽는다.
- toolController 누락 시 OnToolSlot*에서 NullReferenceException 가능.
- FindAction은 throwIfNotFound=false라 이름이 틀려도 예외 대신 null이 되며 이동 일부만 조용히 실패할 수 있다.


2.2 PlayerMovement.cs [HIGH]
-----------------------------

전체 역할
- 일반 수평 이동, 지상/공중 가속, 점프 버퍼/코요테 타임, 가변 점프와 낙하 제한을 처리한다.
- Flame과 UpDraft 접촉 시 일반 중력/점프 대신 각각의 특수 이동 모드로 전환한다.

주요 변수

inputHandler
- 현재 이동/달리기/점프 입력 상태를 제공한다.
- 모든 이동 모드가 같은 입력 원천을 쓰기 위해 필요하다.
- Awake에서 보완하고 Update/FixedUpdate 계열이 읽는다.

walkSpeed / runSpeed
- 걷기와 달리기의 목표 수평 속도다.
- IsRunning 조건에 따라 이동 결과를 바꾼다.
- HandleMovement/HandleFlameMovement/HandleUpDraftMovement에서 사용한다.

groundAcceleration / groundDeceleration / airAcceleration / airDeceleration
- 지상/공중에서 목표 속도에 접근하거나 멈추는 속도다.
- 즉시 속도 변경 대신 조작감을 만들기 위해 필요하다.
- HandleMovement가 IsGrounded와 입력 유무에 따라 선택한다.

turnAccelerationMultiplier
- 현재 진행 방향과 입력 방향이 반대일 때 가속도를 높이는 배수다.
- 방향 전환이 둔해지는 것을 막는다.
- HandleMovement에서 조건부로 사용한다.

jumpForce / coyoteTime / jumpBufferTime
- 점프 초기 Y속도, 발판을 떠난 뒤 허용 시간, 착지 전 입력 보존 시간이다.
- 조작 허용 범위를 넓혀 점프 입력을 안정화한다.
- UpdateJumpTimers/TryJump가 사용하고 counter를 변경한다.

fallGravityMultiplier / jumpCutGravityMultiplier / maxFallSpeed
- 낙하 가속, 버튼을 일찍 놓은 상승 가속, 최대 하강 속도를 정한다.
- 점프 높이 제어와 빠른 낙하를 만든다.
- ApplyJumpGravity가 rb.gravityScale/linearVelocity를 변경한다.

bodyCollider / groundLayer / groundCheckDistance / minGroundNormalY
- 지면 Cast 원본, 대상 레이어, 거리, 허용 표면 법선 기준이다.
- 벽을 지면으로 잘못 판정하지 않고 점프 가능 여부를 결정한다.
- Awake에서 filter를 구성하고 IsGrounded가 사용한다.

flameLayer / flameContactCount
- 불꽃 영역 레이어와 현재 접촉 Collider 수다.
- 다중 Collider가 겹쳐도 마지막 접촉이 끝날 때까지 Flame 모드를 유지한다.
- Trigger enter/exit와 OnDisable에서 변경한다.

flame 이동 변수들
- horizontalSpeedMultiplier/Acceleration, riseSpeed/Acceleration, sinkSpeed/Acceleration, resistance를 저장한다.
- Flame 안에서 중력 대신 좌우/상승/하강 속도를 직접 제어한다.
- HandleFlameMovement가 사용한다.

activeUpDrafts
- 현재 접촉한 UpDraftZone 목록이다.
- 겹치는 구역과 비활성/파괴된 구역을 안전하게 추적한다.
- EnterUpDraft/ExitUpDraft/GetActiveUpDraft/OnDisable에서 변경된다.

rb / defaultGravityScale / coyoteTimeCounter / jumpBufferCounter
- 물리 본체, 원래 중력, 현재 남은 점프 허용 시간을 저장한다.
- 모드 전환 후 중력을 복구하고 점프 조건을 판단한다.

주요 함수

Awake()

역할:
- 물리 참조와 기본 중력을 저장하고 레이어/Collider/input/filter를 준비한다.

호출 시점: Unity 초기화 시 1회.

동작 방식:
1. Rigidbody2D와 기본 gravityScale을 저장한다.
2. flameLayer가 0이면 이름 Flame으로 자동 설정한다.
3. bodyCollider/inputHandler가 없으면 같은 오브젝트에서 찾는다.
4. frictionlessMaterial이 있으면 bodyCollider에 적용한다.
5. groundLayer만 포함하고 Trigger를 제외하는 ContactFilter2D를 구성한다.
6. 이후 지면 판정과 모든 이동 모드가 준비된다.

사용/변경 변수: rb, defaultGravityScale, flameLayer, bodyCollider, inputHandler, groundContactFilter
연결 코드: Rigidbody2D, Collider2D, PhysicsMaterial2D, PlayerInputHandler

Update() / UpdateJumpTimers()

역할:
- 렌더 프레임 기준으로 코요테/점프 버퍼 시간을 갱신한다.

호출 시점: Update가 매 프레임 UpdateJumpTimers를 호출.

동작 방식:
1. Flame 또는 UpDraft면 두 counter를 0으로 만들고 들어온 JumpPressed를 소비한 뒤 종료한다.
2. 일반 상태에서는 IsGrounded()를 호출한다.
3. 지면이며 Y속도가 거의 상승 중이 아니면 coyoteTimeCounter를 최대값으로 재설정한다. 아니면 시간만큼 감소시킨다.
4. JumpPressed면 jumpBufferCounter를 설정하고 입력을 소비한다. 입력이 없으면 감소시킨다.
5. 다음 FixedUpdate의 TryJump가 두 counter를 함께 검사한다.

사용/변경 변수: coyoteTimeCounter, jumpBufferCounter, inputHandler.JumpPressed
연결 코드: IsGrounded(), PlayerInputHandler.ConsumeJumpInput()

FixedUpdate()

역할:
- 현재 이동 모드 하나를 선택해 물리 속도를 변경한다.

호출 시점: Unity 물리 프레임.

동작 방식:
1. IsInFlame이면 HandleFlameMovement 후 즉시 종료한다.
2. 아니고 IsInUpDraft면 HandleUpDraftMovement 후 종료한다.
3. 둘 다 아니면 HandleMovement -> TryJump -> ApplyJumpGravity 순서로 실행한다.
4. 결과적으로 Flame이 UpDraft와 일반 이동보다 우선한다.

사용/변경 변수: rb, flameContactCount, activeUpDrafts
연결 코드: 세 이동 처리 함수

HandleMovement()

역할:
- 일반 상태 수평 속도를 입력과 지면 상태에 맞춰 부드럽게 바꾼다.

호출 시점: 일반 상태의 FixedUpdate.

동작 방식:
1. IsRunning으로 목표 최고 속도를 고른다.
2. MoveInput X로 targetHorizontalSpeed를 만든다.
3. 입력 유무와 IsGrounded 결과로 가속/감속 값을 선택한다.
4. 현재 속도와 목표 부호가 반대면 turnAccelerationMultiplier를 곱한다.
5. MoveTowards로 새 X속도를 계산하고 rb.linearVelocity에 반영한다.
6. 캐릭터가 지상/공중 조작감에 맞게 이동하거나 정지한다.

사용/변경 변수: 속도/가속 변수, rb.linearVelocity
연결 코드: PlayerInputHandler, IsGrounded()

TryJump()

역할:
- 점프 버퍼와 코요테 시간이 모두 남았을 때 실제 점프를 실행한다.

호출 시점: 일반 상태 FixedUpdate에서 수평 이동 뒤.

동작 방식:
1. 두 counter 중 하나라도 0 이하면 종료한다.
2. rb Y속도를 jumpForce로 교체한다.
3. 두 counter를 0으로 만들어 중복 점프를 막는다.
4. 게임에서 즉시 상승이 시작된다.

사용/변경 변수: rb.linearVelocity, jumpBufferCounter, coyoteTimeCounter
연결 코드: UpdateJumpTimers()

ApplyJumpGravity()

역할:
- 수직 방향과 버튼 유지 여부에 따라 중력을 바꾸고 낙하 속도를 제한한다.

호출 시점: 일반 상태 FixedUpdate 마지막.

동작 방식:
1. Y속도가 음수면 defaultGravityScale*fallGravityMultiplier.
2. Y속도가 양수이고 JumpHeld가 false면 jumpCutGravityMultiplier.
3. 그 외에는 기본 중력으로 복구한다.
4. Y속도가 -maxFallSpeed보다 작으면 제한한다.
5. 낙하는 빨라지고 버튼을 짧게 누르면 낮게 점프한다.

사용/변경 변수: rb.gravityScale/linearVelocity, defaultGravityScale, gravity multiplier
연결 코드: PlayerInputHandler.JumpHeld

HandleFlameMovement()

역할:
- Flame 안에서 중력을 끄고 점프 유지 여부로 상승/완만한 하강을 만든다.

호출 시점: IsInFlame인 FixedUpdate.

동작 방식:
1. gravityScale=0으로 만든다.
2. 수평 입력과 달리기 속도에 Flame 배수를 적용해 X속도를 접근시킨다.
3. JumpHeld면 Y속도를 riseSpeed 쪽으로 접근시킨다.
4. 아니면 양의 Y속도를 0 이하로 자르고 -sinkSpeed 쪽으로 접근시킨다. 너무 빨리 떨어질 때는 resistance를 쓴다.
5. 계산한 XY를 rb.linearVelocity에 적용한다.

사용/변경 변수: flame 이동 변수, rb.gravityScale/linearVelocity
연결 코드: PlayerInputHandler

HandleUpDraftMovement()

역할:
- 활성 상승기류가 요청하는 수직 속도를 추종한다.

호출 시점: UpDraft 안이며 Flame이 아닌 FixedUpdate.

동작 방식:
1. GetActiveUpDraft()로 사용할 구역을 얻고 없으면 종료한다.
2. 중력을 0으로 만든다.
3. 입력 기반 X 목표 속도에 UpDraft 배수를 적용한다.
4. 플레이어 Collider 중심 Y를 구한다.
5. UpDraft.GetDesiredVerticalSpeed()로 목표 Y속도를 받고 RiseAcceleration으로 접근한다.
6. 플레이어가 구역 상단 근처에서 부유한다.

사용/변경 변수: activeUpDrafts, rb, bodyCollider, upDraftHorizontal*
연결 코드: UpDraftZone.GetDesiredVerticalSpeed()

EnterUpDraft() / ExitUpDraft() / GetActiveUpDraft()

역할:
- 접촉 상승기류 목록을 관리하고 현재 사용할 유효 구역을 반환한다.

호출 시점:
- UpDraftZone Trigger enter/stay/exit/disable.

동작 방식:
1. Enter는 null/중복을 거르고 목록에 추가, 점프 timer 초기화, 중력 0.
2. Exit는 해당 구역을 제거하고 Flame/다른 UpDraft가 없을 때 기본 중력 복구.
3. Get은 뒤에서부터 null/비활성 항목을 제거하고 마지막 유효 구역을 반환한다.
4. 겹친 구역에서도 하나가 끝났다고 모드가 즉시 해제되지 않는다.

사용/변경 변수: activeUpDrafts, coyoteTimeCounter, jumpBufferCounter, rb.gravityScale
연결 코드: UpDraftZone

OnTriggerEnter2D() / OnTriggerExit2D()

역할:
- Flame 레이어 접촉 수를 세고 첫 진입/마지막 퇴장 때 중력을 전환한다.

호출 시점: Unity 2D Trigger 이벤트.

동작 방식:
1. other.layer가 flameLayer에 포함되는지 검사한다.
2. 진입이면 count 증가, 점프 timer 초기화, 첫 접촉에서 중력 0.
3. 퇴장이면 count를 0 이상으로 감소한다.
4. Flame과 UpDraft 모두 없을 때만 기본 중력 복구.

사용/변경 변수: flameContactCount, rb.gravityScale, jump counters
연결 코드: Physics2D Trigger

IsGrounded()

역할:
- 몸 Collider 아래 Cast 결과에서 걸을 수 있는 법선을 가진 지면을 찾는다.

호출 시점: UpdateJumpTimers와 HandleMovement.

동작 방식:
1. bodyCollider를 아래로 groundCheckDistance만큼 Cast한다.
2. ground filter에 맞는 hit만 받는다.
3. hit normal.y가 minGroundNormalY 이상인 것이 하나라도 있으면 true.
4. 점프 허용과 지상 가속 여부가 바뀐다.

사용 변수: bodyCollider, groundContactFilter, groundHits, minGroundNormalY
연결 코드: Collider2D.Cast()

OnDisable()
- Flame/UpDraft 상태를 비우고 기본 중력을 복구한다. 비활성화 후 특수 모드가 고착되지 않게 한다.

버그 발생 시 먼저 확인
- inputHandler/bodyCollider가 같은 플레이어에 연결됐는지.
- Ground 레이어, Collider Cast 거리와 법선 기준. 점프 불가 시 최우선이다.
- Flame Collider가 Trigger이며 Flame 레이어인지.
- Flame과 UpDraft가 겹치면 Flame이 무조건 우선한다.
- 외부 스크립트가 gravityScale을 바꾸면 이 스크립트의 기본값 복구와 충돌한다.


2.3 PlayerToolController.cs [HIGH]
---------------------------------

전체 역할
- 도구 슬롯, 현재 도구와 슬롯 index를 관리하고 선택 변경 이벤트를 발행한다.

주요 변수
- toolSlots: 슬롯별 ToolData 목록. 선택/추가/삭제의 원본이다. Loadout이 Awake에서 채운다.
- startingSlotIndex: 별도 loadout이 없을 때 Start에서 우선 선택할 index다.
- currentTool: 상호작용에 전달할 현재 ToolData다. 선택/슬롯 변경 함수가 변경한다.
- currentSlotIndex: 현재 슬롯 위치. 휠 순환의 시작점이며 -1은 선택 없음이다.
- CurrentToolChanged: UI 등 외부에 현재 도구 변경을 알리는 이벤트다.

Start()

역할: 현재 도구가 아직 없으면 시작 슬롯 또는 첫 유효 도구를 선택한다.
호출 시점: Unity Start.
동작 방식:
1. currentTool이 이미 있으면 종료한다.
2. startingSlotIndex의 도구가 있으면 그 슬롯 선택 후 종료한다.
3. 아니면 SelectFirstAvailableTool()을 호출한다.
4. 결과적으로 가능한 경우 현재 도구가 생긴다.
변수: currentTool, startingSlotIndex, currentSlotIndex
연결: SelectToolSlot(), SelectFirstAvailableTool()

SelectToolSlot(int)

역할: 지정 슬롯을 현재 도구로 만든다.
호출 시점: InputHandler, Loadout, 내부 선택 함수.
동작 방식:
1. GetToolAtSlot으로 범위와 null을 함께 검사한다.
2. 유효하지 않으면 false.
3. 유효하면 currentSlotIndex/currentTool 변경.
4. CurrentToolChanged 이벤트 발행 후 true.
5. 이후 PlayerInteraction의 도구 조건이 달라진다.
변수: currentSlotIndex, currentTool, CurrentToolChanged
연결: ToolData, PlayerInteraction.CurrentTool

SelectNextTool() / SelectPreviousTool() / SelectRelativeTool(int)

역할: 현재 위치 기준으로 null 슬롯을 건너뛰며 순환 선택한다.
호출 시점: InputHandler 마우스 휠.
동작 방식:
1. 슬롯 0개면 종료한다.
2. 현재 index가 잘못됐으면 첫 유효 도구를 선택한다.
3. 최대 슬롯 수만큼 modulo index를 검사한다.
4. 첫 non-null 슬롯을 SelectToolSlot한다.
5. 모든 슬롯이 비면 변경하지 않는다.
변수: toolSlots, currentSlotIndex
연결: SelectToolSlot()

SetToolSlot(int, ToolData)

역할: 슬롯을 필요하면 늘린 뒤 도구를 지정하고 현재 선택 일관성을 유지한다.
호출 시점: PlayerToolLoadout 또는 런타임 장비 변경 코드.
동작 방식:
1. 음수 index면 false.
2. EnsureSlotExists로 목록을 null 슬롯까지 확장한다.
3. 지정 슬롯 값을 바꾼다.
4. 현재 슬롯이었다면 currentTool도 변경한다. null이면 선택을 해제하고 다른 첫 도구를 찾는다.
5. 현재 도구가 없는데 새 non-null 도구가 들어오면 그 슬롯을 선택한다.
변수: toolSlots, currentTool, currentSlotIndex
연결: EnsureSlotExists(), SelectFirstAvailableTool(), CurrentToolChanged

AddTool() / RemoveTool() / ClearToolSlot() / ClearTools()

역할: 런타임 도구 보유 목록을 추가/제거/초기화한다.
호출 시점: 현재 직접 호출자는 Loadout의 ClearTools뿐이며 나머지는 확장 API다.
동작 방식:
1. Add는 null 거부, 중복이면 기존 index 반환, 빈 슬롯 또는 끝에 추가, 현재 도구가 없으면 선택.
2. Remove는 IndexOf 후 ClearToolSlot으로 위임.
3. ClearToolSlot은 슬롯을 null로 만들고 현재 슬롯이면 다른 첫 도구를 선택하거나 null 이벤트 발행.
4. ClearTools는 목록/현재 상태를 비우고 기존 선택이 있었으면 null 이벤트 발행.
5. 결과적으로 상호작용 가능한 대상이 즉시 달라진다.
변수: toolSlots, currentTool, currentSlotIndex, CurrentToolChanged
연결: PlayerToolLoadout, PlayerInteraction

SelectFirstAvailableTool() / GetToolAtSlot() / EnsureSlotExists()
- 첫 non-null 선택, 안전한 슬롯 조회, 목록 확장용 보조 함수다. 선택 결과 또는 목록 크기를 변경한다.

버그 발생 시 먼저 확인
- SampleScene의 toolSlots는 비어 있고 PlayerToolLoadout이 Sword/Axe/Pickaxe를 Awake(-100)에 넣는다.
- currentTool만 Inspector에 지정하면 Start가 반환해 currentSlotIndex=-1이며 변경 이벤트가 발행되지 않을 수 있다.
- 같은 ToolData asset인지 확인한다. 같은 이름의 별도 asset은 다른 도구다.


2.4 PlayerToolLoadout.cs [MEDIUM]
---------------------------------

전체 역할
- 게임 시작 시 ToolController 슬롯을 시작 도구 목록과 선택 슬롯으로 초기화한다.

주요 변수
- toolController: 초기화할 대상. Awake에서 같은 오브젝트를 보완 탐색한다.
- startingTools: index 순서 그대로 슬롯에 들어갈 ToolData 목록이다.
- startingSlotIndex: 초기 선택할 슬롯이다.
- replaceExistingTools: true면 기존 슬롯을 모두 지우고 시작 목록으로 교체한다.

Awake()

역할: Controller를 찾고 즉시 loadout을 적용한다.
호출 시점: 실행 순서 -100인 Unity Awake.
동작 방식:
1. 참조가 없으면 GetComponent로 찾는다.
2. ApplyLoadout()을 호출한다.
3. 일반 PlayerToolController.Start보다 먼저 슬롯이 준비된다.
변수: toolController
연결: ApplyLoadout(), PlayerToolController

ApplyLoadout()

역할: 설정된 도구 목록과 현재 선택을 Controller에 반영한다.
호출 시점: Awake 또는 외부 재초기화 요청.
동작 방식:
1. Controller가 없으면 종료한다.
2. replaceExistingTools면 ClearTools.
3. startingTools를 index별 SetToolSlot.
4. startingSlotIndex 선택을 시도한다.
5. 실패하면 첫 유효 도구를 선택한다.
6. 플레이어가 처음 사용할 도구가 결정된다.
변수: startingTools, startingSlotIndex, replaceExistingTools
연결: ClearTools(), SetToolSlot(), SelectToolSlot(), SelectFirstAvailableTool()

버그 확인: 시작 도구 null 슬롯, 잘못된 startingSlotIndex, Controller 누락, 실행 중 ApplyLoadout 재호출 시 기존 도구 삭제 여부.


2.5 PlayerInteraction.cs [HIGH]
-------------------------------

전체 역할
- 마우스가 가리킨 IInteractable을 레이어/거리/도구 조건으로 검사한다.
- Resource 레이어는 클릭 홀드 중 일정 간격으로 반복 실행하고, 그 외 대상은 짧은 지연 뒤 한 번 실행한다.

주요 변수
- interactionPoint: 거리 측정 기준 Transform. 플레이어 중심 대신 손/앞쪽 지점을 쓸 수 있다.
- interactionRange: 클릭 Collider의 가장 가까운 점까지 허용 거리다.
- holdDuration: 자원 Interact를 반복 호출하는 간격이다.
- quickInteractionDelay: 몬스터/동굴의 클릭 후 실행 지연이다.
- interactableLayers: OverlapPoint가 탐색할 복수 레이어 마스크다.
- mainCamera: 화면 마우스 좌표를 월드 좌표로 바꾼다.
- toolController/inputHandler/inventory/inventoryUI: 현재 도구, 공격 상태, 인벤토리 context, UI 열림 차단에 사용한다.
- currentInteractable/currentInteractableLayer: 현재 클릭 세션의 대상과 분류 레이어다.
- resourceLayer: 이름 Resource의 layer index. 홀드/빠른 실행을 나눈다.
- holdTimer/quickInteractionTimer: 실행까지 누적 시간이다.
- isHolding/isQuickInteractionPending: 현재 세션 모드다.

Awake()

역할: 카메라와 같은 플레이어의 관련 컴포넌트, Resource layer를 캐시한다.
호출 시점: Unity 초기화.
동작 방식:
1. Camera.main과 Tool/Input/Inventory/UI 컴포넌트를 찾는다.
2. Inventory가 같은 오브젝트에 없으면 부모에서 재탐색한다.
3. Resource layer index를 이름으로 구한다.
4. 이후 Update의 모든 판정 참조가 준비된다.
변수: 모든 참조, resourceLayer
연결: Camera, PlayerToolController, PlayerInputHandler, InventorySystem, InventoryUIController

Update()

역할: 클릭 세션을 시작/유지/취소/완료한다.
호출 시점: 매 렌더 프레임.
동작 방식:
1. inventoryUI가 열려 있으면 CancelInteraction, 공격 입력 소비 후 종료한다.
2. Mouse.current에서 pressed/held/released를 읽는다.
3. InputHandler가 있으면 두 입력 원천을 OR로 합친다.
4. 새 눌림이며 아무 세션도 없으면 StartInteraction.
5. 홀드 중이며 버튼 유지면 HoldInteraction, 해제면 CancelInteraction.
6. quick pending이면 UpdateQuickInteraction.
7. 마지막에 InputHandler 공격 프레임 플래그를 소비한다.
8. 결과적으로 한 클릭 세션만 진행된다.
변수: isHolding, isQuickInteractionPending, click 상태
연결: Mouse, PlayerInputHandler, InventoryUIController

StartInteraction()

역할: 클릭 대상을 확정하고 자원 홀드 또는 빠른 실행 모드로 진입한다.
호출 시점: Update에서 새 클릭 감지.
동작 방식:
1. FindClickedInteractable로 대상과 layer를 얻는다.
2. 대상이 없으면 Cancel.
3. CurrentTool을 CanUseTool에 전달한다.
4. 도구가 맞지 않으면 Cancel.
5. 대상 컴포넌트 GameObject의 layer가 Resource면 holdTimer=0/isHolding=true.
6. 아니면 quickTimer=0/pending=true.
7. 이후 즉시 실행하지 않고 해당 timer 경로로 간다.
변수: currentInteractable/layer, timers, mode flags
연결: IInteractable.CanUseTool(), CurrentTool, FindClickedInteractable()

HoldInteraction()

역할: 자원 홀드가 holdDuration을 채울 때마다 Interact를 실행한다.
호출 시점: isHolding이며 버튼을 계속 누른 Update.
동작 방식:
1. holding/대상 유효성을 검사하고 없으면 취소한다.
2. holdTimer에 deltaTime을 더한다.
3. duration 미만이면 기다린다.
4. 도달하면 currentInteractable.Interact(this)를 호출한다.
5. 호출 중 Unity Object가 파괴됐는지 검사해 취소한다.
6. 아직 존재해도 CanInteract=false면 취소한다.
7. 계속 가능하면 holdTimer=0으로 다음 채집 주기를 시작한다.
8. 자원 타격 수가 증가하고 조건에 따라 드롭/파괴된다.
변수: holdTimer, currentInteractable, isHolding
연결: IInteractable.Interact/CanInteract()

UpdateQuickInteraction()

역할: 몬스터/동굴 등 비자원 대상을 지연 후 한 번 실행한다.
호출 시점: quick pending인 Update.
동작 방식:
1. quickTimer 누적.
2. delay 미만이면 대기.
3. 대상 null 또는 CanInteract=false면 취소.
4. Interact(this)를 한 번 호출한다.
5. 항상 CancelInteraction으로 세션 종료.
6. 몬스터 HP 감소 또는 동굴 전환이 시작된다.
변수: quickInteractionTimer, currentInteractable, isQuickInteractionPending
연결: IInteractable.Interact()

FindClickedInteractable(out int)

역할: 마우스 위치에 있고 상호작용 거리 안인 첫 유효 IInteractable을 찾는다.
호출 시점: StartInteraction.
동작 방식:
1. Mouse.current.position을 읽는다.
2. mainCamera.ScreenToWorldPoint로 월드 좌표 변환.
3. 합친 레이어 마스크로 Physics2D.OverlapPoint 단일 Collider 검색.
4. Collider 부모에서 IInteractable을 찾고 CanInteract 검사.
5. Collider.ClosestPoint와 interactionPoint 거리를 계산해 range 검사.
6. 구현 Component의 GameObject layer를 분류값으로 반환한다.
7. 모든 조건을 통과한 대상만 반환한다.
변수: mainCamera, interactionPoint/range, interactableLayers
연결: Mouse, Camera, Physics2D, IInteractable

CancelInteraction()
- 두 모드/두 timer/현재 대상/layer를 모두 초기화한다. UI 열림, 클릭 해제, 실패, 완료 때 호출된다.

GetCombinedInteractableLayerMask()
- interactableLayers 각 value를 OR로 합친다. 목록 null이면 0이어서 아무 대상도 검출하지 못한다.

버그 발생 시 먼저 확인
- Camera.main 태그, interactionPoint, Interactable/Resource 마스크, Collider와 부모 IInteractable.
- 자원 판정은 IResourceProvider가 아니라 컴포넌트 GameObject의 Resource layer다.
- 게임패드 Attack만 있고 Mouse.current가 없는 장치에서 FindClickedInteractable이 null을 역참조할 수 있다.
- OverlapPoint 단일 결과라 겹친 Collider 중 원하지 않는 대상이 선택될 수 있다.
- 클릭 시작 뒤 플레이어가 멀어져도 거리를 다시 검사하지 않는다. 세션 중 이동으로 범위를 벗어나도 실행된다.


3. HIGH — 자원, 드롭, 인벤토리
================================

3.1 자원 상호작용 공통 구현 8개 [HIGH]
----------------------------------------

해당 파일
- CoalInteractable.cs
- Flame_StoneInteractable.cs
- Floating_OreInteractable.cs
- SteelInteractable.cs
- StoneInteractable.cs
- Storm_StoneInteractable.cs
- ThicketInteractable.cs
- TreeInteractable.cs

전체 역할
- 선택 도구의 종류와 티어를 검사하고, 일정 타격마다 확률적으로 ResourceData 드롭을 만든다.
- 최대 타격 수에 도달하면 고갈 상태로 바꾸고 자원 GameObject를 파괴한다.

주요 변수 — 8개 파일 공통

resourceData
- 생성할 드롭 프리팹과 수량 쌍을 저장한 ResourceData asset 참조다.
- 자원 종류별 결과물을 데이터로 분리하기 위해 필요하다.
- Interact에서 null 검사하고 SpawnResourceDrops가 읽는다.

tier
- 자원 채집 난이도 등급이다.
- 현재 도구 tier와 차이를 계산해 드롭 확률을 정한다.
- ShouldDropResource가 읽는다.

oneTierGapDropChance / twoOrMoreTierGapDropChance
- 도구가 자원보다 1티어 또는 2티어 이상 낮을 때 성공 확률이다.
- 낮은 도구로도 채집은 가능하되 실패 위험을 주기 위해 필요하다.
- ShouldDropResource가 읽는다.

itemDropSpawner
- 실제 드롭 GameObject 생성과 레이어/수량 초기화를 위임할 대상이다.
- Interact에서 null 검사하고 SpawnResourceDrops가 호출한다.

dropOffset / dropRadius
- 자원 중심에서 드롭 분산 중심과 반경을 정한다.
- 여러 드롭이 같은 위치에 완전히 겹치지 않게 한다.
- GetRandomDropPosition이 사용한다.

addItemInterval
- 몇 번째 상호작용마다 드롭을 시도할지 저장한다.
- 모든 타격마다 보상을 주지 않는 채집 주기를 만든다.
- Interact의 modulo 조건이 읽고 IResourceProvider setter가 최소 1로 제한한다.

maxInteractCount
- 파괴되기 전 허용할 총 상호작용 횟수다.
- 자원 수명을 결정한다.
- Interact가 읽는다.

interactCount / isDepleted
- 현재까지 성공 여부와 무관한 타격 수, 더 상호작용 가능한지 저장한다.
- Interact가 증가/설정하고 CanInteract가 읽는다.

CanInteract()

역할: 고갈되지 않은 자원만 선택 가능하게 한다.
호출 시점: PlayerInteraction의 대상 탐색과 반복 후 검사.
동작 방식:
1. isDepleted의 반대를 반환한다.
2. false면 새 상호작용과 다음 홀드 반복이 중단된다.
변수: isDepleted
연결: PlayerInteraction.FindClickedInteractable/HoldInteraction()

CanUseTool(ToolData)

역할: 자원 종류에 맞는 도구인지 판정한다.
호출 시점: PlayerInteraction.StartInteraction.
동작 방식:
1. ToolData null 검사.
2. 나무/덤불은 Axe, 광물은 Pickaxe인지 비교.
3. tier는 여기서 차단 조건이 아니며 드롭 확률에만 영향한다.
4. false면 홀드 세션 자체가 시작되지 않는다.
변수: 전달된 ToolData.ToolType
연결: ToolData, PlayerInteraction

Interact(PlayerInteraction)

역할: 한 번의 채집 타격을 기록하고 보상/고갈을 처리한다.
호출 시점: PlayerInteraction.HoldInteraction이 holdDuration마다 호출.
동작 방식:
1. isDepleted 또는 context null이면 종료한다.
2. ResourceData/Spawner가 없으면 종료하며 interactCount도 증가하지 않는다.
3. interactCount를 1 증가시킨다.
4. count가 AddItemInterval의 배수인지 검사한다.
5. 배수이면 ShouldDropResource(CurrentTool)를 호출하고 성공일 때 SpawnResourceDrops.
6. count가 MaxInteractCount 이상인지 검사한다.
7. 도달하면 isDepleted=true 후 Destroy(gameObject).
8. 게임에서 드롭이 생길 수 있고 마지막에는 자원이 사라진다.
변수: interactCount, isDepleted, resourceData, itemDropSpawner
연결: PlayerInteraction.CurrentTool, ShouldDropResource(), SpawnResourceDrops(), Destroy()

ShouldDropResource(ToolData)

역할: 현재 도구 tier로 이번 보상 성공 여부를 결정한다.
호출 시점: 드롭 간격 타격의 Interact.
동작 방식:
1. tool null이면 false.
2. tierGap=자원 tier-도구 tier 계산.
3. 0 이하면 항상 true.
4. 1이면 oneTierGap, 2 이상이면 twoOrMoreTierGap 선택.
5. Random.value와 비교해 bool 반환.
6. 실패해도 interactCount는 이미 소비된 상태다.
변수: tier, 확률 변수
연결: ToolData.Tier, UnityEngine.Random

SpawnResourceDrops()

역할: ResourceData의 모든 유효 드롭 항목을 생성한다.
호출 시점: ShouldDropResource가 true인 interval 타격.
동작 방식:
1. DropCount와 랜덤 시작 각도를 구한다.
2. 각 index를 TryGetDrop으로 검증한다.
3. 유효하면 GetRandomDropPosition으로 위치 계산.
4. ItemDropSpawner.Spawn(prefab, position, amount) 호출.
5. 드롭 오브젝트가 월드에 나타난다.
변수: resourceData, itemDropSpawner, dropOffset/radius
연결: ResourceData.TryGetDrop(), ItemDropSpawner.Spawn()

GetRandomDropPosition()
- 전체 dropCount로 원을 나눈 기본 각도에 작은 jitter와 반경 50~100% 랜덤을 적용한다.
- transform.position+dropOffset+randomOffset을 반환하며 상태는 바꾸지 않는다.

개별 기본값과 연결
- CoalInteractable: Pickaxe, tier 1, interval 3, max 6 → 3/6회 드롭 시도.
- Flame_StoneInteractable: Pickaxe, tier 3, interval 3, max 4 → 3회만 드롭 시도.
- Floating_OreInteractable: Pickaxe, tier 3, interval 3, max 8 → 3/6회.
- SteelInteractable: Pickaxe, tier 1, interval 3, max 8 → 3/6회.
- StoneInteractable: Pickaxe, tier 2, interval 3, max 5 → 3회.
- Storm_StoneInteractable: Pickaxe, tier 3, interval 3, max 4 → 3회.
- ThicketInteractable: Axe, tier 1, interval 2, max 4 → 2/4회.
- TreeInteractable: Axe, tier 1, interval 2, max 6 → 2/4/6회.

버그 발생 시 먼저 확인
- 프리팹의 Resource layer, Collider2D, resourceData, itemDropSpawner.
- PlayerInteraction 마스크와 현재 도구 종류.
- maxInteractCount가 interval보다 작으면 보상 없이 파괴된다.
- 마지막 타격의 확률도 실패할 수 있다.
- 같은 로직이 8개 파일에 복제되어 한 파일만 수정하면 종류별 동작이 달라진다.


3.2 ResourceData.cs [MEDIUM]
----------------------------

전체 역할
- 한 자원 또는 몬스터가 떨어뜨릴 GameObject 프리팹과 수량을 index 쌍으로 저장하는 ScriptableObject다.

주요 변수
- dropPrefabs: 드롭 프리팹 목록. ItemDropInteractable이 들어 있는 프리팹이어야 한다.
- dropAmounts: 같은 index 프리팹의 생성 수량이다.
- DropCount: 두 목록 중 짧은 길이. 불일치에서 안전하게 접근하기 위해 필요하다.

TryGetDrop(int, out GameObject, out int)

역할: index의 프리팹/수량 쌍이 실제 생성 가능한지 검증해 반환한다.
호출 시점: 자원과 몬스터의 Spawn*Drops.
동작 방식:
1. out 값을 null/0으로 초기화한다.
2. index가 0~DropCount-1 밖이면 false.
3. 두 목록에서 같은 index를 읽고 수량을 0 이상으로 제한한다.
4. prefab non-null이며 amount>0일 때만 true.
5. 호출자는 true 항목만 Spawn한다.
변수: dropPrefabs, dropAmounts, DropCount
연결: ItemDropSpawner를 사용하는 모든 드롭 생산자

OnValidate()
- Inspector 변경 시 목록 길이 불일치를 알리고 모든 수량을 0 이상으로 보정한다.

버그 확인: 두 목록 길이, null prefab, 0 amount, 프리팹 내부 ItemDropInteractable/ItemData.


3.3 ItemDropSpawner.cs [HIGH]
------------------------------

전체 역할
- 드롭 프리팹을 생성하고 ItemDrop 레이어와 수량을 적용한다.
- ItemDrop 레이어가 Ground 외 모든 레이어와 충돌하지 않도록 전역 Physics2D 충돌 행렬을 설정한다.

주요 변수
- dropParent: 생성 드롭을 정리할 부모 Transform. null이면 씬 루트에 생성된다.
- itemDropLayer/groundLayer: 이름으로 찾은 layer index다. 생성 layer와 충돌 정책에 필요하다.

Awake()

역할: 레이어를 찾고 충돌 행렬을 구성한다.
호출 시점: Unity 초기화.
동작 방식:
1. NameToLayer로 ItemDrop/Ground를 찾는다.
2. 하나라도 없으면 이후 충돌 설정 없이 종료한다.
3. ConfigureItemDropCollisions를 호출한다.
4. ItemDrop이 Ground에만 물리 충돌하도록 프로젝트 전역 상태가 바뀐다.
변수: itemDropLayer, groundLayer
연결: Physics2D.IgnoreLayerCollision()

Spawn(GameObject, Vector3, int)

역할: 검증된 드롭 인스턴스를 만들고 획득 수량을 설정한다.
호출 시점: 자원/몬스터의 드롭 함수.
동작 방식:
1. prefab null 또는 amount<=0이면 null 반환.
2. 지정 위치/부모로 Instantiate.
3. itemDropLayer가 유효하면 모든 자식까지 해당 layer로 변경.
4. 루트에서 ItemDropInteractable을 찾는다.
5. 없으면 생성물을 파괴하고 null.
6. 있으면 Initialize(amount) 후 GameObject 반환.
7. 게임 월드에 자동 획득 가능한 드롭이 생긴다.
변수: dropParent, itemDropLayer
연결: ItemDropInteractable.Initialize(), Instantiate/Destroy

ConfigureItemDropCollisions()
- 0~31 레이어를 순회해 Ground만 충돌 허용하고 나머지는 ignore한다. 이 변경은 해당 오브젝트만이 아니라 전역 collision matrix에 적용된다.

SetLayerRecursively()
- 생성 루트와 모든 자식 layer를 동일하게 바꾼다.

버그 확인: 레이어 이름, 드롭 루트의 ItemDropInteractable, Rigidbody2D, dropParent. 다른 시스템이 ItemDrop 충돌을 원하면 전역 행렬 변경을 먼저 확인한다.


3.4 ItemDropInteractable.cs [HIGH]
---------------------------------

전체 역할
- 드롭을 잠시 물리 낙하시킨 뒤 플레이어 인벤토리 근처에서 흡인/축소하고, 무게 제한 안이면 적재 후 파괴한다.

주요 변수
- itemData: 인벤토리에 들어갈 아이템 정의. 프리팹마다 연결된다.
- amount: 이 드롭이 주는 수량. Initialize가 설정한다.
- pickupEnableDelay/pickupEnableTime: 생성 직후 획득을 막는 시간/절대 시각이다.
- attractionDistance/pickupDistance: 흡인 시작 거리와 실제 적재 거리다.
- attractionSpeed: Rigidbody 위치가 플레이어로 접근하는 속도다.
- minimumScaleMultiplier/originalScale: 접근 중 축소 하한과 원래 크기다.
- pickupRetryDelay/nextPickupAttemptTime: 무게 초과 시 매 물리 프레임 재요청하지 않도록 한다.
- cachedInventory: 모든 드롭이 공유하는 첫 InventorySystem 캐시다.
- inventory/pickupTarget: 이 인스턴스가 사용할 인벤토리와 Transform이다.
- rb/isAttracting: 물리 본체와 현재 흡인 모드다.

Awake()
- Rigidbody와 원래 scale을 저장하고 FindPickupTarget을 시도한다. 아직 인벤토리가 없어도 FixedUpdate에서 재시도한다.

Initialize(int)

역할: 드롭 수량과 획득 가능 시각을 설정한다.
호출 시점: ItemDropSpawner.Spawn 직후.
동작 방식:
1. 수량을 0 이상으로 제한한다.
2. pickupEnableTime=현재 시간+delay.
3. ItemData가 있으면 오브젝트 이름을 아이템명 x수량으로 바꾼다.
4. delay 동안 자연 물리가 동작하고 이후 자동 획득 대상이 된다.
변수: amount, pickupEnableTime, itemData
연결: ItemDropSpawner

FixedUpdate()

역할: 거리 기반 흡인, 축소, 획득을 수행한다.
호출 시점: 매 물리 프레임.
동작 방식:
1. pickupEnableTime 전이면 종료한다.
2. itemData/amount/target이 유효하지 않으면 종료한다.
3. 현재 거리 계산.
4. attractionDistance 밖이면 기존 흡인을 StopAttraction하고 종료한다.
5. pickupDistance 안이며 TryCollect 성공이면 종료한다.
6. 그 외 BeginAttraction으로 중력/속도를 정리한다.
7. 거리에 따라 minimum~original scale을 보간한다.
8. MoveTowards 위치를 rb.MovePosition에 적용한다.
9. 드롭이 플레이어로 날아오며 작아진다.
변수: 모든 거리/속도/scale/물리/target 상태
연결: FindPickupTarget(), TryCollect(), Begin/StopAttraction(), Rigidbody2D

FindPickupTarget()

역할: 사용할 InventorySystem과 그 Transform을 확보한다.
호출 시점: Awake와 FixedUpdate.
동작 방식:
1. 현재 두 참조가 모두 있으면 true.
2. static cache가 없으면 FindFirstObjectByType<InventorySystem>().
3. instance inventory와 target을 cache로 설정한다.
4. 둘 다 유효한지 반환한다.
변수: cachedInventory, inventory, pickupTarget
연결: InventorySystem

BeginAttraction() / StopAttraction()

역할: 흡인 물리 상태 진입/종료.
호출 시점: FixedUpdate의 거리 조건.
동작 방식:
1. Begin은 중복이면 종료, isAttracting=true, gravity=0, 속도=0, WakeUp.
2. Stop은 isAttracting=false, gravity=0, 속도=0, Sleep, scale 복구.
3. 흡인 중에는 낙하하지 않고 직접 MovePosition된다.
변수: isAttracting, rb, transform.localScale
연결: Rigidbody2D

TryCollect()

역할: 인벤토리 추가를 시도하고 성공한 드롭을 제거한다.
호출 시점: pickupDistance 이내 FixedUpdate.
동작 방식:
1. retry 시각 전이면 false.
2. inventory.TryAddItem(itemData, amount) 호출.
3. 실패하면 다음 시도 시각 설정 후 false.
4. 성공하면 amount=0, Destroy(gameObject), true.
5. 인벤토리 수량/무게/UI가 변하고 드롭이 사라진다.
변수: nextPickupAttemptTime, inventory, itemData, amount
연결: InventorySystem.TryAddItem()

OnValidate()
- 거리/속도/지연을 유효 범위로 보정하며 pickupDistance가 attractionDistance를 넘지 않게 한다.

버그 확인
- Spawner.Initialize가 호출되지 않으면 amount=0이라 획득되지 않는다.
- StopAttraction이 원래 gravityScale을 복원하지 않고 0으로 고정해 멀어진 드롭이 공중 정지할 수 있다.
- InventorySystem이 여러 개면 static FindFirst 결과가 의도한 플레이어인지 확인한다.
- 무게 초과는 드롭 삭제가 아니라 retry 상태다.


3.5 InventoryItem.cs [LOW]
--------------------------

전체 역할
- 한 아이템 종류의 ItemData와 수량을 묶는 직렬화 가능한 스택 데이터다.

주요 변수
- itemData: 종류/무게/아이콘 원본.
- quantity: 현재 스택 수량.
- TotalWeight: itemData.Weight*quantity 결과. InventorySystem/UI가 읽는다.

InventoryItem(ItemData, int)
- 새 종류를 처음 추가할 때 InventorySystem이 호출해 두 값을 저장한다.

버그 확인: null itemData나 0/음수 quantity를 자체 방어하지 않으므로 InventorySystem 밖에서 생성/직렬화할 때 주의한다.


3.6 InventorySystem.cs [HIGH]
------------------------------

전체 역할
- ItemData 기준 스택 목록과 최대 무게를 관리하고 변경 이벤트로 UI를 갱신한다.

주요 변수
- items: 실제 InventoryItem 스택 목록이다. 추가/제거의 영속 상태다.
- maxWeight: 런타임 허용 최대 무게. CurrentWeight와 비교한다.
- settingsWeight: Awake에서 maxWeight를 계산하는 기준값이다.
- logInterval/logTimer: 주기적 상태 출력용이며 게임 상태에는 영향이 없다.
- InventoryChanged: 성공한 추가/제거를 UI에 알린다.

Awake()

역할: 최대 무게를 settingsWeight의 120%로 설정한다.
호출 시점: Unity 초기화.
동작 방식:
1. settingsWeight + settingsWeight*0.2를 계산한다.
2. maxWeight를 무조건 덮어쓴다.
3. 이후 모든 추가 요청의 한도가 결정된다.
변수: settingsWeight, maxWeight

Update() / LogInventory()
- Update가 logTimer를 누적하고 interval에 도달하면 초기화 후 LogInventory를 호출한다.
- LogInventory는 null 항목을 건너뛰고 각 스택과 총 무게를 출력할 뿐 상태를 바꾸지 않는다.

AddItem(ItemData, int)
- 반환값이 필요 없는 호출자를 위해 TryAddItem으로 위임한다. 실제 로직은 TryAddItem에 있다.

TryAddItem(ItemData, int)

역할: 입력과 무게를 검증한 뒤 기존 스택 증가 또는 새 스택 추가.
호출 시점: ItemDropInteractable.TryCollect 또는 외부 보상 코드.
동작 방식:
1. itemData null 또는 amount<=0이면 false.
2. 현재 총 무게와 추가 무게, 예상 무게 계산.
3. 예상 무게>maxWeight면 상태 변경 없이 false.
4. items가 null이면 새 List 생성.
5. itemData 참조가 같은 기존 스택 검색.
6. 있으면 quantity 증가, 없으면 새 InventoryItem 추가.
7. InventoryChanged 발행 후 true.
8. 드롭 수집/UI 표시/현재 무게가 바뀐다.
변수: items, maxWeight, InventoryChanged
연결: ItemData, InventoryItem, ItemDropInteractable, InventoryUIController

RemoveItem(ItemData, int)

역할: 충분한 수량이 있을 때 스택을 감소/삭제한다.
호출 시점: InventoryUIController.ConfirmDiscard 또는 외부 소비 코드.
동작 방식:
1. 인수/items 유효성 검사.
2. 같은 ItemData 스택 검색. 없으면 false.
3. 보유 수량<요청이면 false.
4. quantity 감소.
5. 0 이하면 목록에서 스택 제거.
6. InventoryChanged 발행 후 true.
7. UI/무게/아이템 순서가 갱신된다.
변수: items, InventoryChanged
연결: InventoryUIController

GetItemCount() / HasItem()
- 같은 ItemData 참조의 수량을 찾고, HasItem은 요청 수량 이상인지 반환한다. 상태를 바꾸지 않는다.

GetTotalWeight()
- null 스택/데이터를 건너뛰고 TotalWeight 합계를 반환한다. TryAddItem과 UI가 호출한다.

버그 확인
- SampleScene maxWeight=10은 Awake에서 settingsWeight=100 기준 120으로 덮어써진다.
- ItemData.Weight가 음수면 제한을 우회할 수 있다.
- ItemData asset 참조 동일성으로 합친다. ID가 같아도 별도 asset이면 다른 스택이다.
- 아이템 종류 제한은 없지만 UI는 20칸뿐이다.

=============================

4.1 IDamageable.cs [LOW]
------------------------

전체 역할
- 피해를 받을 수 있는 객체가 사망 여부와 TakeDamage를 공통 방식으로 제공하게 하는 계약이다.

주요 멤버
- IsDead: 공격/스폰 로직이 더 처리할 수 있는 대상인지 판단한다.
- TakeDamage(int): 양의 피해를 적용하는 진입점이다.

호출 흐름
1. AggMonsterController가 playerDamageable.TakeDamage를 호출한다.
2. Sword 공격은 각 몬스터 Interact가 자신의 TakeDamage를 호출한다.
3. MonsterSpawnManager2D는 구현 여부와 IsDead로 몬스터 유효성/생존 수를 판단한다.

연결: PlayerAssimilate, AggMonsterController, PeMonsterController, MonsterSpawnManager2D
버그 확인: 새 IDamageable 몬스터를 추가하면 스폰 매니저의 PlayerAssimilate 제외와 prefab 이름/타입 카운트 조건도 확인한다.


4.2 PlayerAssimilate.cs [HIGH]
--------------------------------

전체 역할
- 플레이어의 동화도를 사실상 체력으로 저장하고 피해/회복, UI 변경, 사망 이벤트를 제공한다.

주요 변수
- maxAssimilation: 동화도 상한. OnValidate가 최소 1로 제한한다.
- currentAssimilation: 현재 값. 0이면 IsDead=true다.
- AssimilationChanged: 값이 실제로 변할 때 현재/최대값을 구독자에게 전달한다.
- Died: TakeDamage 때문에 0에 도달했을 때 발행한다.

Assimilate(int)

역할: 양수/음수 amount를 현재 값에 더하고 범위를 제한한다.
호출 시점: AssimilatelZone의 회복, TakeDamage의 감소, 외부 시스템.
동작 방식:
1. 이전 값을 저장한다.
2. current+amount를 0~max 범위로 Clamp한다.
3. 실제 값이 달라졌을 때만 AssimilationChanged를 발행한다.
4. HUD target 값과 IsDead 계산 결과가 달라질 수 있다.
사용/변경 변수: currentAssimilation, maxAssimilation, AssimilationChanged
연결: LiquidCircleGauge.HandleAssimilationChanged(), AssimilatelZone

TakeDamage(int)

역할: 유효한 피해를 동화도 감소로 변환하고 사망 이벤트를 발생시킨다.
호출 시점: AggMonsterController.AttackRoutine.
동작 방식:
1. amount<=0 또는 이미 IsDead면 종료한다.
2. Assimilate(-amount)를 호출한다.
3. 감소 후 아직 살아 있으면 종료한다.
4. 0이면 Died 이벤트를 발행한다.
5. 현재 Died 구독자가 없어 게임오버/입력 차단은 자동으로 일어나지 않는다.
사용/변경 변수: currentAssimilation, Died
연결: IDamageable, AggMonsterController, Assimilate()

OnValidate()
- 최대값을 1 이상, 현재값을 0~최대 범위로 보정한다.

버그 확인
- Died 구독자 부재가 가장 큰 기능 공백이다.
- 죽은 뒤 Assimilate(양수)는 회복을 허용하지만 부활 상태 전환 이벤트는 없다.
- 초기값 변경 이벤트는 자동 발행하지 않는다. HUD는 Configure에서 직접 읽는다.


4.3 PeMonsterController.cs [HIGH]
----------------------------------

전체 역할
- 평상시 좌우 배회하고 Sword 피격 후 플레이어 반대 방향으로 일정 시간 도망가며, 사망 시 아이템을 드롭한다.

주요 변수
- playerTarget: 도망 방향 계산 기준 플레이어 Transform. 첫 공격 context 또는 검색으로 설정된다.
- rb/bodyCollider/spriteRenderer: 이동, 사망 물리 차단, 방향 표시 컴포넌트다.
- maxHealth/currentHealth/isDead: 체력과 생존 상태다.
- wanderSpeed, minimum/maximumWanderTime, wanderDirection, nextWanderChangeTime: 배회 속도/현재 방향/다음 변경 시각이다.
- fleeSpeed/fleeDuration/fleeDirection/fleeEndTime: 피격 후 도주 상태를 결정한다.
- dropData/itemDropSpawner/dropRadius/dropOffset: 사망 드롭 구성이다.

Awake()

역할: 컴포넌트/Spawner를 확보하고 체력과 첫 배회 방향을 초기화한다.
호출 시점: Unity 초기화.
동작 방식:
1. 비어 있는 rb/collider/renderer를 같은 오브젝트에서 찾는다.
2. Spawner가 없으면 씬 첫 ItemDropSpawner를 찾는다.
3. currentHealth=maxHealth.
4. SelectNewWanderDirection으로 첫 방향/시간 설정.
5. 몬스터가 이동 가능한 초기 상태가 된다.

FixedUpdate()

역할: 사망/도주/배회 중 하나의 이동 상태를 실행한다.
호출 시점: 물리 프레임.
동작 방식:
1. isDead면 종료.
2. Time.time<fleeEndTime이면 UpdateFleeDirection 후 fleeSpeed로 이동하고 종료.
3. 아니면 Wander.
4. 피격 동안 도주하고 시간이 끝나면 배회로 돌아간다.
변수: isDead, fleeEndTime, rb.linearVelocity
연결: UpdateFleeDirection(), MoveHorizontally(), Wander()

CanInteract() / CanUseTool()
- 살아 있을 때만 상호작용 가능하며 ToolData가 non-null Sword일 때만 공격을 허용한다. PlayerInteraction이 호출한다.

Interact(PlayerInteraction)

역할: 플레이어 Sword 상호작용을 몬스터 피해로 변환한다.
호출 시점: PlayerInteraction.UpdateQuickInteraction.
동작 방식:
1. context와 현재 도구를 재검사한다.
2. playerTarget을 context.transform으로 저장한다.
3. CurrentTool.Damage로 TakeDamage.
4. HP가 감소하고 생존 시 도주, 0이면 사망한다.
변수: playerTarget, currentHealth
연결: PlayerInteraction.CurrentTool, TakeDamage()

TakeDamage(int)

역할: 체력 감소 후 도주 또는 사망을 선택한다.
호출 시점: Interact 또는 다른 IDamageable 공격.
동작 방식:
1. amount<=0/isDead면 종료.
2. currentHealth를 0 이상으로 감소.
3. 0이면 Die 후 종료.
4. 생존하면 BeginFleeing.
변수: currentHealth, isDead
연결: Die(), BeginFleeing()

BeginFleeing() / UpdateFleeDirection() / FindPlayerTarget()

역할: 플레이어 반대 X방향과 도주 종료 시간을 관리한다.
호출 시점: 생존 피격 및 도주 물리 프레임.
동작 방식:
1. playerTarget이 없으면 PlayerAssimilate를 씬에서 찾는다.
2. 몬스터 X-플레이어 X의 부호를 fleeDirection으로 설정한다.
3. 차이가 거의 없거나 target이 없으면 기존 배회 반대 또는 랜덤 방향을 선택한다.
4. Begin은 fleeEndTime=현재+duration.
5. 이후 FixedUpdate가 fleeSpeed를 사용한다.
변수: playerTarget, fleeDirection, fleeEndTime, wanderDirection
연결: PlayerAssimilate, MoveHorizontally()

Wander() / SelectNewWanderDirection()
- 변경 시각이 지나면 좌/우 랜덤 방향과 다음 지속 시간을 선택하고 wanderSpeed로 이동한다.

MoveHorizontally() / FaceDirection()
- rb X속도를 direction*speed로 교체하고 SpriteRenderer.flipX로 방향을 표시한다. Y속도는 보존한다.

Die() / SpawnDeathDrops()

역할: 몬스터를 비활성 물리 상태로 만들고 유효 드롭을 생성한 뒤 파괴한다.
호출 시점: HP 0.
동작 방식:
1. 중복 사망을 막고 isDead=true.
2. 속도 0, rb.simulated=false, collider disabled.
3. dropData/spawner가 있으면 항목별 랜덤 위쪽 offset으로 Spawn.
4. Destroy(gameObject).
5. 몬스터가 사라지고 자동 획득 드롭이 남는다.
변수: isDead, rb, bodyCollider, drop 설정
연결: ResourceData.TryGetDrop(), ItemDropSpawner.Spawn()

버그 확인
- 낭떠러지/벽/발판 끝 감지 로직이 없다.
- 도주 방향은 X축만 보며 같은 X에서는 fallback이다.
- Spawner를 FindFirstObjectByType으로 찾으므로 다중 Spawner 씬을 확인한다.
- Rigidbody2D/Collider2D/ground physics와 dropData 연결.


4.4 AggMonsterController.cs [HIGH]
-----------------------------------

전체 역할
- 배회하다 플레이어가 추적 반경에 들어오면 X축 추적하고 공격 반경에서 windup 후 동화도 피해를 준다. Sword 피격과 사망 드롭도 처리한다.

주요 변수
- playerTarget/playerDamageable: 추적 Transform과 피해 인터페이스. FindPlayerTarget이 설정한다.
- rb/bodyCollider/spriteRenderer: 이동/사망/방향 표시.
- maxHealth/currentHealth/isDead: 체력/사망 상태.
- wanderSpeed/chaseSpeed/chaseDistance: 기본 이동과 추적 전환 조건.
- minimum/maximumWanderTime, wanderDirection, nextWanderChangeTime: 배회 상태.
- attackDistance/attackDamage: 공격 진입 거리와 PlayerAssimilate 감소량.
- attackWindup/attackRecovery/attackCooldown: 공격 전/후 정지와 다음 공격 가능 시간.
- nextAttackTime/isAttacking/attackRoutine: 공격 진행 상태와 중복 방지.
- dropData/itemDropSpawner/dropRadius/dropOffset: 사망 보상.

Awake()
- 비어 있는 물리/렌더러/Spawner 참조 보완 → currentHealth=maxHealth → 첫 배회 방향/변경 시각 설정 순으로 초기화한다.

FixedUpdate()

역할: 사망, 배회, 추적, 공격 중 현재 행동을 결정한다.
호출 시점: 물리 프레임.
동작 방식:
1. isDead면 종료한다.
2. 플레이어를 못 찾으면 Wander한다.
3. playerDamageable이 사망했으면 Wander한다.
4. 플레이어까지 전체 2D 거리와 X방향을 계산하고 좌우 방향을 표시한다.
5. isAttacking이면 X속도를 0으로 하고 종료한다.
6. attackDistance 이내면 정지하고 cooldown이 끝났을 때 AttackRoutine을 시작한다.
7. attackDistance 밖이지만 chaseDistance 이내면 플레이어 X방향으로 chaseSpeed 이동한다.
8. 그 밖은 Wander한다.
9. 게임에서 거리별 AI 상태가 바뀐다.
사용/변경 변수: playerTarget, playerDamageable, isAttacking, nextAttackTime, rb.linearVelocity
연결: FindPlayerTarget(), AttackRoutine(), Wander(), MoveHorizontally()

CanInteract() / CanUseTool() / Interact()

역할: 살아 있고 Sword를 사용한 요청만 피해로 바꾼다.
호출 시점: PlayerInteraction의 탐색/시작/빠른 실행.
동작 방식:
1. CanInteract는 !isDead 반환.
2. CanUseTool은 tool non-null과 Sword를 검사.
3. Interact는 context/current tool을 재검증한다.
4. CurrentTool.Damage로 TakeDamage를 호출한다.
5. 몬스터 HP가 감소한다.
사용/변경 변수: isDead, currentHealth
연결: PlayerInteraction.CurrentTool, ToolData, TakeDamage()

TakeDamage(int)
- amount<=0 또는 isDead면 무시한다. 그 외 currentHealth를 0 이상으로 감소시키고 0이면 Die한다. 수동형과 달리 피격 경직/도주는 없다.

AttackRoutine()

역할: 공격 준비, 명중 재검사, 회복, cooldown을 순서대로 처리한다.
호출 시점: 공격 거리이며 Time.time>=nextAttackTime인 FixedUpdate.
동작 방식:
1. isAttacking=true, X속도 정지.
2. attackWindup 동안 대기.
3. 자신이 살아 있고 target을 찾았으면 현재 거리를 다시 계산한다.
4. 여전히 attackDistance 안, damageable 존재, 플레이어 생존이면 TakeDamage(attackDamage).
5. attackRecovery 동안 대기.
6. nextAttackTime=현재+cooldown.
7. isAttacking=false, routine=null.
8. 플레이어 동화도가 감소하고 일정 시간 뒤 다시 공격 가능해진다.
사용/변경 변수: isAttacking, attackRoutine, nextAttackTime, 공격 시간/피해
연결: IDamageable.TakeDamage(), PlayerAssimilate

FindPlayerTarget()
- Inspector target이 있으면 그 Transform의 IDamageable을 캐시하고 true다. 없으면 씬 첫 PlayerAssimilate를 찾아 Transform/인터페이스로 저장한다. 찾지 못하면 false다.

Wander() / SelectNewWanderDirection()
- 변경 시각이 지나면 좌/우 랜덤 방향과 다음 지속 시간을 고르고 wanderSpeed로 이동한다.

MoveHorizontally() / StopHorizontalMovement() / FaceDirection()
- X속도를 direction*speed로 바꾸거나 0으로 만든다. Y속도는 유지한다. SpriteRenderer.flipX로 방향을 표시한다.

Die() / SpawnDeathDrops()

역할: 진행 중 공격을 중단하고 물리/Collider를 끈 뒤 드롭을 생성하고 파괴한다.
동작 방식:
1. 중복 사망 검사 후 isDead=true.
2. attackRoutine이 있으면 StopCoroutine.
3. X속도 정지, rb.simulated=false, collider disabled.
4. ResourceData의 유효 항목을 위쪽 랜덤 위치에 Spawner로 생성.
5. Destroy(gameObject).

OnValidate()
- 체력/거리/배회 시간 범위를 보정하며 attackDistance가 chaseDistance를 넘지 않게 한다.

버그 확인
- 공격/추적 거리는 2D 전체 거리지만 실제 이동은 X축뿐이라 높이 차가 크면 접근하지 못한다.
- 벽/낭떠러지 회피가 없다.
- SampleScene attackDamage는 코드 기본 10이 아니라 직렬화된 2다.
- target Transform에 IDamageable이 바로 없으면 playerDamageable이 null일 수 있다.


4.5 MonsterSpawnManager2D.cs [HIGH]
-------------------------------------

전체 역할
- 프리팹별 목표 생존 수를 주기적으로 계산하고, 부족한 몬스터를 카메라 좌우 화면 밖의 지면 위에 보충한다.

주요 변수
- MonsterSpawnRule.prefab/targetCount: 종류별 생성 원본과 유지할 생존 수.
- targetCamera: 화면 밖 계산 기준 카메라.
- allowedSpawnArea: 선택값. 계산 위치가 이 Collider 안인지 추가 제한한다.
- spawnParent: 생성 몬스터 부모.
- spawnRules: 모든 종류별 규칙 목록.
- spawnCheckInterval/spawnImmediately/nextSpawnCheckTime: 보충 검사 스케줄.
- minimum/maximumDistanceOutsideCamera: 카메라 좌우 끝에서 추가로 떨어질 랜덤 거리.
- maximumSpawnAttempts: 한 규칙의 위치 탐색 반복 상한.
- groundLayers/groundRayStartHeight/groundRayDistance/groundClearance: 지면 Raycast와 배치 Y 계산.
- monsterLayers/minimumMonsterSpacing: 기존 몬스터와 최소 간격 검사.

Awake()
- targetCamera가 없으면 Camera.main을 사용한다. groundLayers=0이면 Ground, monsterLayers=0이면 Interactable 이름 레이어를 기본값으로 설정한다.

OnEnable() / Update()

역할: 첫 검사와 반복 검사 시각을 관리한다.
호출 시점: 활성화/매 프레임.
동작 방식:
1. OnEnable은 immediate에 따라 지금 또는 interval 뒤 시각을 설정한다.
2. Update는 아직 시각 전이면 종료한다.
3. 도달하면 다음 시각을 예약하고 SpawnMissingMonsters를 호출한다.
4. 프레임마다가 아닌 주기마다 보충한다.
사용/변경 변수: nextSpawnCheckTime
연결: SpawnMissingMonsters()

SpawnMissingMonsters()

역할: 규칙별 부족 여부를 확인하고 한 마리 생성을 시도한다.
호출 시점: Update 또는 외부 수동 호출.
동작 방식:
1. 카메라가 없으면 다시 Camera.main, 여전히 없으면 종료한다.
2. 각 rule의 null/prefab null을 건너뛴다.
3. CountAliveMonsters(prefab)>=targetCount면 건너뛴다.
4. 부족하면 TrySpawn(rule)를 한 번 호출한다.
5. 한 검사에서 규칙당 최대 한 마리만 생성된다.
사용 변수: spawnRules, targetCamera
연결: CountAliveMonsters(), TrySpawn()

TrySpawn(MonsterSpawnRule)

역할: 프리팹과 최대 시도 횟수 내 위치를 검증해 인스턴스를 만든다.
동작 방식:
1. IsValidMonsterPrefab 검사.
2. 프리팹 반폭과 루트-바닥 offset 계산.
3. attempt마다 TryFindOffscreenGroundPosition 호출.
4. 위치 실패 또는 IsTooCloseToAnotherMonster면 다음 시도.
5. 통과하면 Instantiate 후 true.
6. 모두 실패하면 false.
사용 변수: maximumSpawnAttempts, spawnParent
연결: prefab bounds 보조 함수, Physics2D, Instantiate

TryFindOffscreenGroundPosition()

역할: 화면 밖 X와 해당 X의 지면 Y를 찾는다.
동작 방식:
1. GetCameraWorldBounds로 world min/max 계산.
2. 좌/우와 바깥 거리를 랜덤 선택.
3. 프리팹 반폭까지 더해 완전히 밖인 spawnX 계산.
4. 카메라 위에서 아래로 Ground Raycast.
5. 지면 없으면 false.
6. hit Y+prefab bottom offset+clearance로 위치 계산.
7. allowed area가 있으면 OverlapPoint 검사.
8. IsCompletelyOutsideCamera로 마지막 확인.

GetCameraWorldBounds() / IsCompletelyOutsideCamera()
- 카메라 z 거리에서 viewport (0,0)/(1,1)을 world 좌표로 바꾸고 프리팹 좌우 끝이 화면 밖인지 판단한다.

IsTooCloseToAnotherMonster()
- spacing<=0이면 false다. monsterLayers의 OverlapCircleAll 중 부모 IDamageable이 하나라도 있으면 true다.

IsValidMonsterPrefab() / TryGetMonsterController()
- 자식 Collider2D와 PlayerAssimilate가 아닌 IDamageable MonoBehaviour가 있는지 검사한다.

CountAliveMonsters() / HasPrefabInstanceName()

역할: 해당 프리팹에서 나온 같은 컨트롤러 타입의 살아 있는 씬 객체 수를 센다.
동작 방식:
1. prefab controller 타입을 구한다.
2. 씬의 모든 MonoBehaviour를 찾는다.
3. 정확히 같은 타입인지 검사한다.
4. 자신/조상 이름이 prefab name 또는 name(Clone)인지 검사한다.
5. IDamageable이며 !IsDead이면 증가한다.
6. 목표 수 판정에 사용한다.

GetPrefabHalfWidth() / GetPrefabBottomOffset() / TryGetCombinedSpriteBounds()
- SpriteRenderer 결합 bounds를 우선, Collider bounds를 fallback으로 사용해 화면 밖 X와 지면 위 Y를 계산한다.

OnValidate()
- 검사 시간/거리/시도/간격 값을 유효 범위로 보정하고 maximum outside가 minimum 이상이 되게 한다.

버그 확인
- 확정: SampleScene spawnRules가 빈 배열이라 자동 생성이 전혀 없다.
- 인스턴스 이름을 바꾸면 생존 카운트에서 빠져 과다 스폰될 수 있다.
- 한 규칙당 5초마다 최대 한 마리라 목표 수까지 느리게 채워진다.
- allowedSpawnArea null은 제한 없음이다. Ground ray 길이/카메라 높이/레이어를 확인한다.
- monsterLayers=Interactable이 자원/다른 IDamageable과 섞이는지 확인한다.


5. MEDIUM — 동화 구역과 HUD
===========================

5.1 AssimilatelZone.cs [MEDIUM]
--------------------------------

전체 역할
- PlayerAssimilate가 Trigger 안에 머무는 동안 일정 “초 간격”마다 동화도 1을 회복한다.

주요 변수
- assimilateAmountPerTick: 이름과 Tooltip은 양처럼 보이지만 실제로는 호출 간격(초)이다.
- currentPlayerAssimilation: 현재 구역 안에서 회복할 플레이어.
- elapsedTime: 다음 회복까지 누적된 시간.
- playerColliderCount: 같은 플레이어의 여러 Collider 접촉 수. 하나가 나가도 다른 것이 남으면 회복을 유지한다.

Update()

역할: 플레이어가 있을 때 경과 시간을 회복 tick으로 변환한다.
호출 시점: 매 프레임.
동작 방식:
1. current player가 없으면 종료한다.
2. elapsedTime에 deltaTime을 더한다.
3. interval을 최소 0.01로 계산한다.
4. elapsed>=interval인 동안 interval을 빼고 Assimilate(1).
5. 긴 프레임에도 누락된 tick을 while로 보충한다.
6. 플레이어 동화도와 HUD가 1씩 오른다.
사용/변경 변수: elapsedTime, assimilateAmountPerTick
연결: PlayerAssimilate.Assimilate()

OnTriggerEnter2D()

역할: 구역 안 플레이어와 Collider 수를 등록한다.
호출 시점: 2D Trigger 진입.
동작 방식:
1. other 부모에서 PlayerAssimilate를 찾는다.
2. 다른 플레이어가 이미 등록됐으면 무시한다.
3. 같은 플레이어의 추가 Collider면 count만 증가한다.
4. 첫 Collider면 current player 설정, count=1, timer=0.
사용/변경 변수: currentPlayerAssimilation, playerColliderCount, elapsedTime

OnTriggerExit2D()

역할: Collider가 모두 나갔을 때 회복을 종료한다.
동작 방식:
1. 나간 Collider의 PlayerAssimilate가 현재 대상인지 검사한다.
2. count를 0 이상으로 감소시킨다.
3. 아직 1 이상이면 유지한다.
4. 0이면 player 참조와 timer를 초기화한다.

OnDisable() / OnValidate()
- Disable은 player/time/count를 모두 초기화한다.
- Validate는 interval을 최소 0.01초로 제한한다.

버그 확인
- SampleScene 값 2.5~5는 초당 회복량이 아니라 “1 회복마다 걸리는 초”다.
- Collider isTrigger, Rigidbody2D 이벤트 조건, 다중 Collider enter/exit 균형.
- 한 구역은 동시에 서로 다른 플레이어 한 명만 추적한다.


5.2 LiquidCircleGauge.cs [MEDIUM]
---------------------------------

전체 역할
- 값을 0~1로 정규화해 액체 Shader fill을 부드럽게 이동시키고 값 변화 때 파동을 강화한다. PlayerAssimilate 이벤트를 구독할 수 있다.

주요 변수
- waterImage/percentageText/liquidShader: 표시 대상과 Material 생성 원본.
- minValue/maxValue/currentValue: 논리 값 범위와 최신 실제 값.
- displayedFill/targetFill: 현재 화면 fill과 도달해야 할 fill.
- fillSpeed: 화면 fill 변화 속도.
- valueChangeWaveStrength/waveRecoverySpeed/waveBoost: 값 변화 시 파동 증가와 기본값 1 복귀.
- assimilationSource: 구독할 PlayerAssimilate.
- runtimeMaterial: 게이지 전용 Material 인스턴스. 공유 material 오염을 막는다.
- hasInitialValue: 첫 값은 애니메이션 없이 즉시 표시할지 판단한다.

Awake() / OnEnable() / OnDisable() / OnDestroy()
- Awake: material 확보 후 초기 currentValue를 즉시 반영한다.
- OnEnable: source 이벤트를 구독한다.
- OnDisable: 중복/유령 콜백 방지를 위해 구독 해제한다.
- OnDestroy: Image에서 material을 떼고 런타임 material을 파괴한다.

Configure(Image, TMP_Text, Shader, PlayerAssimilate)

역할: HUD가 런타임 생성한 참조와 데이터 소스를 주입한다.
호출 시점: LiquidCircleGaugeHUD.BuildGauge.
동작 방식:
1. UI/Shader 참조를 저장한다.
2. EnsureMaterial을 호출한다.
3. SetSource로 기존 구독 해제/새 구독/즉시 동기화한다.
4. source null이면 자체 currentValue를 즉시 표시한다.
5. 게이지가 실제 표시 가능한 상태가 된다.

Update()

역할: fill과 wave를 시간에 따라 목표로 이동시켜 표시한다.
호출 시점: 매 프레임.
동작 방식:
1. material을 만들 수 없으면 종료한다.
2. displayedFill을 targetFill 쪽으로 MoveTowards한다.
3. waveBoost를 1 쪽으로 복구한다.
4. ApplyVisuals로 shader/text에 반영한다.
5. unscaledDeltaTime이라 timeScale=0이어도 애니메이션은 계속된다.
사용/변경 변수: displayedFill, targetFill, waveBoost, runtimeMaterial
연결: ApplyVisuals()

SetValue() / SetNormalizedValue() / SetRange()
- SetValue는 SetValueInternal로 위임한다.
- SetNormalizedValue는 0~1로 제한 후 실제 range 값으로 변환한다.
- SetRange는 max가 min보다 최소 간격 이상이 되게 하고 현재값을 다시 적용한다.

SetSource() / SubscribeToSource() / UnsubscribeFromSource() / SyncFromSource()
- 기존 source 이벤트를 제거하고 새 source를 저장한다.
- 활성 상태일 때만 AssimilationChanged를 구독한다.
- source가 있으면 범위를 0~MaxAssimilation, 값을 CurrentAssimilation으로 즉시 동기화한다.

HandleAssimilationChanged() / SetValueInternal()

역할: 새 동화도 값을 target fill과 wave 상태로 변환한다.
동작 방식:
1. handler가 range와 value를 내부 함수에 전달한다.
2. range 유효성 보정 후 currentValue를 Clamp한다.
3. InverseLerp로 nextFill과 기존 target 대비 변화량을 계산한다.
4. 첫 값/immediate면 displayedFill도 즉시 설정한다.
5. 일반 변화면 waveBoost를 1+변화량*strength 이상으로 높인다.
6. ApplyVisuals를 호출한다.

EnsureMaterial() / ApplyVisuals()
- material이 없고 Image/Shader가 있으면 전용 Material을 생성해 Image에 지정한다.
- Apply는 _FillAmount/_WaveBoost와 반올림 퍼센트를 갱신한다.

OnValidate()
- range/current/speed를 보정하고 실행 중이면 새 값을 애니메이션 대상으로 반영한다.

버그 확인: Shader에 _FillAmount/_WaveBoost가 있는지, Configure 호출, source 구독, water Image material, max/min 범위.


5.3 LiquidCircleGaugeHUD.cs [MEDIUM]
------------------------------------

전체 역할
- 좌하단 HUD Canvas와 물/퍼센트/외곽선 계층을 런타임 생성하고 LiquidCircleGauge를 PlayerAssimilate에 연결한다.

주요 변수
- assimilationSource: 표시할 플레이어 동화도.
- outlineSprite/liquidShader: 시각 자산.
- gaugeSize/screenMargin/canvasSortingOrder: 좌하단 배치와 렌더 순서.

Awake() / BuildGauge()

6.1 ResourceSpawnZone2D.cs [HIGH]
------------------------------------

전체 역할
- 지정 Collider 영역 안의 Resource 레이어 IInteractable 개수를 목표치까지 보충한다.
- 새 프리팹 SpriteRenderer AABB가 영역 밖으로 나가거나 기존 자원 이미지와 겹치면 배치를 거부한다.

- targetResourceCount: 영역 안 유지 목표 개수.
- spawnInterval/spawnImmediately/nextSpawnTime: 보충 주기.

- imageSpacing: 후보/기존 이미지 bounds 사이 추가 여백.
- overlapResults/countedResources/occupiedImageBounds: Collider 결과, 중복 제거 Component, AABB 캐시.
- resourceFilter/resourceLayer: Resource layer Trigger 포함 Overlap 필터.

Awake()
- spawnArea가 없으면 자신의 Collider를 쓴다. Resource layer가 없으면 enabled=false. 있으면 해당 layer만 포함하고 Trigger도 허용하는 ContactFilter2D를 구성한다.

OnEnable() / Update()
- 활성화 시 immediate에 따라 nextSpawnTime 설정.
- Update는 시각 도달 → 다음 시각 예약 → CountResourcesInArea가 목표 미만일 때 TrySpawnResource 한 번 실행 순이다.

TrySpawnResource()

역할: 최대 시도 안에서 프리팹과 겹치지 않는 내부 위치를 찾아 하나 생성한다.
동작 방식:
1. CanSpawn으로 영역/목록/목표를 검사한다.
2. BuildOccupiedImageBounds로 기존 자원 AABB를 수집한다.
3. attempt마다 GetRandomValidPrefab을 고른다.
4. 영역 내부 랜덤 점을 찾는다.
5. 후보 prefab의 해당 위치 AABB를 계산한다.
6. 네 모서리가 모두 영역 안인지, 기존 bounds와 겹치는지 검사한다.
7. 통과하면 Instantiate하고 자식까지 Resource layer를 적용한 뒤 true다.
8. 모두 실패하면 false다.
결과: 목표치까지 주기당 최대 자원 하나가 생긴다.

CountResourcesInArea()

역할: 영역 안 서로 다른 Resource IInteractable 개수를 센다.
동작 방식:
1. 영역/layer 유효성을 검사한다.
2. spawnArea.Overlap으로 필터 결과를 수집한다.
3. 자기 Collider와 null을 제외한다.
4. 각 Collider 부모 IInteractable을 찾는다.
5. 구현 Component를 HashSet에 넣어 다중 Collider 중복을 제거한다.
6. Count를 반환한다.

CanSpawn() / GetRandomValidPrefab()
- 영역 활성, 프리팹 목록, 목표>0을 검사한다.
- 랜덤 시작 index부터 순회해 자식 SpriteRenderer가 있는 첫 non-null prefab을 반환한다.

TryGetRandomPointInArea()
- spawnArea.bounds 사각형에서 랜덤 점을 뽑고 실제 Collider.OverlapPoint인 점만 반환한다.

BuildOccupiedImageBounds()
- 영역 내 Resource IInteractable의 결합 SpriteRenderer bounds를 occupied 목록에 저장한다.

TryGetPrefabImageBounds() / TryGetCombinedRendererBounds()
- Renderer들의 world bounds를 합치고 root-center offset을 새 위치에 적용한 뒤 spacing만큼 확장한다.

IsCompletelyInsideArea() / OverlapsExistingImage()
- 후보 AABB 네 모서리의 OverlapPoint와 Bounds.Intersects를 검사한다.

SetLayerRecursively() / OnValidate()
- 생성 루트/자식 layer를 Resource로 맞춘다. Validate는 count/interval/attempt/spacing을 보정하고 spawnArea를 자동 연결한다.

버그 확인

- 자원 Collider/컴포넌트가 Resource layer여야 카운트된다.
- 회전/오목한 영역은 AABB 네 모서리 검사 때문에 배치 가능한 공간도 거부될 수 있다.

6.4 CameraLookAhead.cs [MEDIUM]
--------------------------------

전체 역할
- 이동 입력 방향으로 카메라 수평 시야를 앞당기고 Rigidbody Y속도로 위/아래 시야를 조절한다.
- 낙하 중 Cinemachine Y damping을 0 쪽으로 낮춰 플레이어를 더 빨리 따라간다.

주요 변수
- inputHandler/playerRigidbody/positionComposer: 수평 의도, 수직 실제 속도, 적용할 Cinemachine 컴포넌트.
- horizontalOffset/inputThreshold: 이동 방향 추가 offset과 무시할 작은 입력.
- directionChangeSmoothTime/returnToCenterSmoothTime: 이동/정지 수평 보간 시간.
- upwardOffset/downwardOffset: 상승/낙하 최대 추가 시야.
- verticalVelocityThreshold/velocityForMaximumOffset: 수직 look-ahead 시작/최대 강도 속도 기준.
- verticalLookAheadSmoothTime/verticalReturnToCenterSmoothTime/maximumVerticalOffsetSpeed: Y offset 보간.
- fallFollowEnterSmoothTime/fallFollowExitSmoothTime: 낙하 damping 진입/복귀 시간.
- defaultTargetOffset/defaultPositionDamping: disable 시 복구할 원래 Composer 값.
- current offsets/damping과 velocity 변수: SmoothDamp 연속 상태.

Awake()

역할: Composer/플레이어 참조와 원래 카메라 설정을 저장한다.
동작 방식:
1. Composer null이면 같은 오브젝트에서 찾는다.
2. InputHandler null이면 씬 첫 객체를 찾는다.
3. Rigidbody null이면 InputHandler 오브젝트에서 찾는다.
4. TargetOffset/Damping 기본값을 저장한다.
5. 현재 보간 상태를 기본값으로 초기화한다.

Update()

역할: 현재 입력/속도에서 목표 offset을 계산해 Composer에 반영한다.
호출 시점: 매 프레임.
동작 방식:
1. InputHandler/Composer 없으면 종료한다.
2. X입력이 threshold보다 큰지 검사한다.
3. 이동 중이면 기본 X+방향*offset, 정지면 기본 X를 목표로 선택한다.
4. 상황별 smoothTime으로 current X를 SmoothDamp한다.
5. Rigidbody가 있으면 Y속도의 절대값/낙하 여부를 판정한다.
6. threshold 초과면 InverseLerp 강도와 상승/하강 offset으로 target Y를 계산한다.
7. SetVerticalDamping(isFalling)을 호출한다.
8. 이동/정지별 시간과 max speed로 current Y를 SmoothDamp한다.
9. Composer.TargetOffset을 갱신한다.
10. 화면이 진행/수직 이동 방향을 더 보여준다.

SetVerticalDamping(bool)
- 낙하면 목표 Y damping=0, 아니면 기본값이다. 진입/이탈 시간으로 SmoothDamp한 뒤 Composer.Damping.y만 변경한다.

OnDisable()
- Composer offset/damping을 기본값으로 되돌리고 모든 SmoothDamp velocity를 0으로 초기화한다.

버그 확인: CinemachinePositionComposer가 같은 오브젝트인지, 입력/Rigidbody가 의도한 플레이어인지, 다른 코드가 TargetOffset/Damping을 동시에 수정하는지.


6.5 InfiniteBackground2D.cs [LOW]
---------------------------------

전체 역할
- Renderer가 있는 활성 자식 중 처음 3개를 좌우로 정렬하고, 카메라가 한 조각을 완전히 지나면 반대편 끝으로 옮겨 무한 배경을 만든다.

주요 변수
- RequiredSectionCount=3: 요구 조각 수.
- targetCamera: 카메라 좌우 world 경계 기준.
- recyclePadding: 화면보다 추가로 벗어난 뒤 재활용하게 하는 여백.
- seamOverlap: 조각 경계를 조금 겹쳐 틈을 숨긴다.
- backgroundSections: 실제 순환할 3 Transform.
- isInitialized: 모든 전제조건을 만족했는지.

Awake() / LateUpdate()
- Awake에서 Initialize한다.
- LateUpdate는 실패 상태면 재시도하고 성공 상태에서 RecycleBackgroundSections를 호출한다. 카메라 이동 뒤 최신 위치를 사용한다.

Initialize()

역할: 카메라와 3개 유효 조각을 확보하고 초기 배치를 맞춘다.
동작 방식:
1. 카메라 null이면 Camera.main.
2. 자식 목록을 비운다.
3. Renderer bounds가 있는 자식 중 3개만 추가하고 나머지는 비활성화한다.
4. 카메라 존재/Orthographic/조각 정확히 3개인지 검사한다.
5. X위치 정렬 후 AlignSections한다.
6. isInitialized=true.

RecycleBackgroundSections()

역할: 카메라 좌우 범위에 3조각이 계속 덮이도록 재배치한다.
동작 방식:
1. orthographicSize*aspect로 화면 좌우+padding을 계산한다.
2. 최대 12번 반복해 조각을 위치 정렬한다.
3. 가장 왼쪽이 화면 왼쪽보다 완전히 뒤면 가장 오른쪽 뒤로 이동한다.
4. 가장 오른쪽이 화면 오른쪽보다 완전히 앞이면 가장 왼쪽 앞으로 이동한다.
5. 둘 다 아니면 종료한다.
6. bounds 실패 시 initialized=false로 다음 프레임 재초기화한다.

SortSectionsByPosition() / AlignSections()

Awake()

역할: 참조를 찾고 입력 가능한 UI를 생성한 뒤 시작 상태를 적용한다.
호출 시점: Unity 초기화.
동작 방식:
1. inventory/inputHandler가 없으면 같은 오브젝트에서 찾는다.
2. EnsureEventSystem.
3. BuildUI로 전체 계층 생성.
4. SetOpen(initialOpen).
5. 게임 시작 전 UI가 준비된다.

OnEnable() / OnDisable()
- Inventory가 있으면 기존 동일 handler를 제거한 뒤 InventoryChanged에 구독한다.
- Disable에서 해제해 중복 콜백과 파괴된 UI 호출을 막는다.

Start()
- RefreshSlots를 호출해 시작 인벤토리와 무게를 표시한다.

Update()

역할: 인벤토리 토글 요청을 처리한다.
호출 시점: 매 프레임.
동작 방식:
1. InputHandler가 있으면 ConsumeInventoryToggleInput.
2. 없을 때만 Keyboard.current E키를 fallback으로 읽는다.
3. 요청이 없으면 종료.
4. 현재 IsOpen 반대로 SetOpen.
5. 창이 열리거나 닫힌다. PlayerInteraction은 IsOpen일 때 상호작용을 취소한다.

Toggle() / SetOpen(bool)

역할: UI 열림 상태와 팝업/표시 내용을 일관되게 바꾼다.
동작 방식:
1. IsOpen 변경.
2. 열면 RefreshSlots, 닫으면 CloseDiscardPopup.
3. inventoryRoot 활성 상태 변경.
4. 게임 화면의 인벤토리 표시와 상호작용 차단 조건이 달라진다.

HandleInventoryChanged()

역할: 외부 추가/제거 뒤 폐기 세션과 슬롯을 다시 맞춘다.
호출 시점: InventorySystem.InventoryChanged.
동작 방식:
1. pending item이 있으면 현재 보유량 조회.
2. 0이면 팝업 닫기.
3. 남아 있으면 slider max/value를 새 수량 안으로 보정하고 수량 text 갱신.
4. RefreshSlots.

EnsureEventSystem()
- EventSystem.current가 있으면 종료한다. 없으면 EventSystem+InputSystemUIInputModule GameObject를 생성하고 createdEventSystem에 저장한다.

BuildUI()

역할: Canvas부터 두 패널과 팝업까지 전체 UI 구조를 만든다.
동작 방식:
1. Overlay Canvas/Scaler/Raycaster 생성 및 sorting/reference resolution 설정.
2. 화면 전체 inventoryRoot와 반투명 입력 차단 Image 생성.
3. 중앙 content에 Backpack/Image와 Paper/Image 배치.
4. BuildWeight, BuildSlots, BuildDetails, BuildDiscardPopup 순으로 호출.
5. 이후 저장한 참조를 데이터 갱신 함수가 사용한다.

BuildWeight() / BuildSlots() / CreateSlot()
- Weight TMP를 만든다.
- row*column 크기로 GridLayoutGroup과 슬롯 수를 만든다.
- 각 슬롯에 Background/Button/Icon/Fallback/Quantity/Selection을 만들고 클릭 listener가 캡처한 index로 SelectSlot을 호출하게 한다.

BuildDetails() / BuildDiscardPopup() / CreateSlider()
- 상세 이름/수량/무게와 “버리기” 버튼을 만든다.
- 팝업 blocker/panel/item/amount/slider/확인/취소 버튼을 만들고 listener를 연결한다.
- Slider를 정수 범위로 설정하고 fill/handle 참조를 지정한다.

SelectSlot(int)
- selectedSlotIndex를 바꾸고 선택 테두리와 상세 내용을 갱신한다.

OpenDiscardPopup()

역할: 현재 선택 스택을 폐기 대상으로 설정한다.
동작 방식:
1. GetSelectedItem이 null/데이터 없음/수량<=0이면 종료.
2. pendingDiscardItem 저장.
3. 이름 표시, slider 범위를 1~보유량, 값을 1로 설정.
4. 수량 표시 후 popup 활성.

ConfirmDiscard()

역할: slider 수량만큼 실제 인벤토리에서 제거한다.
동작 방식:
1. inventory/pending null이면 팝업을 닫고 종료.
2. 최신 availableAmount를 조회한다.
3. slider 값을 1~available 범위로 반올림/Clamp한다.
4. available>0이면 RemoveItem.
5. 팝업을 닫는다.
6. InventoryChanged가 슬롯/무게를 갱신한다.

CloseDiscardPopup() / UpdateDiscardAmountText()
- pending item을 null로 하고 팝업을 끈다.
- slider 현재값/max를 반올림해 폐기 수량 문구를 갱신한다.

RefreshSlots()

역할: InventorySystem의 현재 목록을 고정 SlotView에 투영한다.
동작 방식:
1. slot view가 없으면 종료.
2. items와 itemCount 확보.
3. 각 UI index에 같은 inventory index 항목을 매핑.
4. 유효 item이면 icon/수량 표시. icon null이면 ItemName 첫 글자를 표시.
5. 빈 슬롯은 내용을 비운다.
6. UpdateSelection과 UpdateDetails.

UpdateSelection() / UpdateDetails() / GetSelectedItem()

- 선택 item 존재 여부로 상세 root를 켜고 이름/수량/단위무게/총무게를 표시하며, 전체 무게는 항상 갱신한다.
- GetSelectedItem은 items 범위를 검사해 현재 스택 또는 null을 반환한다.

GetFontAsset()
- 기존 runtime asset이 있으면 재사용한다. Malgun Gothic 생성 시도 → 실패하면 LegacyRuntime.ttf → 그래도 실패하면 TMP 기본 font 순이다.

CreateText/CreateButton/CreateUIObject/CreateRectTransform/CreateImage/StretchToParent/SetCenteredRect/SetAnchoredRect
- 런타임 UI 구성용 보조 함수다. 컴포넌트 생성, 부모 설정, anchor/size/색/button listener 대상 준비만 담당한다.

OnDestroy()
- 생성 Canvas, 자신이 만든 EventSystem, runtime font asset을 파괴한다.

버그 확인

- 움직이지 않음: PlayerInput(Player map/Send Messages) -> PlayerInputHandler.MoveInput -> PlayerMovement.inputHandler/Rigidbody2D.
- 점프 안 됨: Jump 액션 -> JumpPressed 소비 -> groundLayer/bodyCollider.Cast/minGroundNormalY -> coyote/buffer.
- 클릭해도 반응 없음: Camera.main -> interactableLayers -> Collider2D -> 부모 IInteractable -> 거리 -> CurrentTool 종류.
- 자원이 채집되지 않음: Resource 레이어 여부 -> holdDuration -> CanUseTool -> resourceData/spawner -> interval/max 횟수.
- 드롭이 안 생김: ResourceData 두 목록/수량 -> ItemDropSpawner 레이어 -> 프리팹 ItemDropInteractable.
- 드롭을 못 먹음: ItemDropInteractable.Initialize amount/itemData -> InventorySystem 탐색 -> 무게 120 제한 -> pickup 거리.
- 인벤토리 UI 문제: InventoryChanged -> RefreshSlots -> 20칸 한계 -> EventSystem/InputSystemUIInputModule/TMP 폰트.
- 몬스터가 안 생김: 현재 가장 먼저 MonsterSpawnManager2D.spawnRules 빈 배열을 수정 -> Ground Raycast -> 화면 밖/간격/허용 영역.
- 몬스터 공격 문제: playerTarget/PlayerAssimilate -> chase/attack distance -> AttackRoutine windup 후 거리 재검사.
- 동화도 HUD 문제: PlayerAssimilate 이벤트 -> HUD shader -> LiquidCircleGauge runtime material/properties.
- 상승기류 문제: BoxCollider2D Trigger -> UpDraftZone players -> PlayerMovement.activeUpDrafts; Flame 중첩 여부.
- 동굴 이동 문제: destination/destinationOffset -> Movement disable -> Confiner bounds 교체 -> Cinemachine target warp.
- 카메라 여백 문제: CameraLookAhead의 input/Rigidbody/PositionComposer 참조와 다른 카메라 스크립트의 동시 수정.
- 배경 틈/순환 문제: 활성 Renderer 자식 정확히 3개, Orthographic Camera, 각 bounds와 seamOverlap.


9. 우선순위가 높은 잠재 결함/주의점
====================================

1) 확정 설정 문제: SampleScene MonsterSpawnManager2D.spawnRules=[] -> 자동 스폰 없음.
2) 입력 장치 결함 가능성: PlayerInteraction은 게임패드 Attack을 받을 수 있지만 대상 좌표는 Mouse.current에만 의존하며 null 방어가 없다.
3) 설정 혼동: InventorySystem.maxWeight Inspector 값은 Awake에서 settingsWeight*1.2로 덮어쓴다.
4) 물리 동작 의심: ItemDropInteractable.StopAttraction이 원래 gravityScale 대신 0으로 고정하고 Sleep한다.
5) 게임 완결성: PlayerAssimilate.Died 이벤트 구독자가 없어 사망 후 게임 상태 전환이 없다.
6) UI/데이터 불일치: InventorySystem 종류 수 무제한, UI는 20개만 표시.
7) 의미가 잘못 읽히기 쉬움: AssimilatelZone.assimilateAmountPerTick은 회복량이 아니라 회복 간격이며 매 tick 회복량은 항상 1.
8) 유지보수 위험: 자원 8종 코드가 거의 완전 복제되어 수정 누락 가능성이 높다.
9) 전환 복구 위험: Cave 이동 코루틴 중 오브젝트가 중단되면 플레이어 컴포넌트가 비활성 상태로 남을 수 있다.
10) 미사용 데이터: ItemData.discountAssimilationRate와 description은 현재 게임 흐름에서 사용되지 않는다.
