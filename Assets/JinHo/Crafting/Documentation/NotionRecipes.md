# Notion 크래프팅 레시피 반영

현재 출처: [크래프팅 레시피](https://app.notion.com/p/3d1da1bd22db809aa1a7fce8ff6fc832), [용광로 UI](https://app.notion.com/p/3d1da1bd22db809aae9adeebadc940b3). 이전 스냅샷: [데이터 베이스](https://app.notion.com/p/8879c4aa4b9c831884ad815a79adf309).

2026-09-29 개정: CSV에는 기존 저장 ID를 보존한 194개 경로가 있으며 59개가 활성화되어 있습니다. 취소선인 흡혈·강철·화염·바람·흑요석 경로와 현재 목록에서 빠진 구 제작 경로는 비활성화했습니다. 철 화살촉은 달궈진 철의 모루 상2/하2/좌1 → 달궈진 철 화살촉 → 담금질 순서입니다. 돌 파편은 숫돌에서 돌 화살촉으로, 찌그러진 철 덩어리는 용광로에서 달궈진 철로 재활용합니다. 용광로 실패 부산물은 재료 종류에 따라 나뉩니다. 기존 연료 최대 50·재료당 3 소비·2.5초 연출을 유지하고 목재 부산물의 연료 값을 1로 맞췄습니다. 실제 플레이의 입력과 전체 제작 연계는 별도 검증이 필요합니다.

2026-10-01 현행 실패 규칙: 위 개정 당시의 실패 부산물 생성과 부분 반환은 사용하지 않습니다. 어느 설비에서든 제작에 실패하면 선택한 재료 전량을 보관함에 돌려놓습니다. 용광로의 제작 시작 시 소비한 연료는 실패해도 복구하지 않습니다. 결과창에는 `실패했습니다.`만 표시합니다. CSV의 과거 부산물 ID와 성공하는 재활용 레시피는 저장 호환성을 위해 유지합니다.

Notion은 읽기만 했습니다. 원래 레시피 스냅샷에 더해 C030에서 전체 아이템 & 장비의 자원·제작물·무기·방어구·전리품·부산물·도구 표를 확인하고 CSV에 반영했습니다.

## 반영 범위

- 총 194개 제작 경로를 저장하고 59개를 활성화했습니다. 기존 경로 ID는 저장 호환성을 위해 삭제하지 않았습니다.
- 현재 나무, 돌, 철, 가죽, 접착제와 부산물 재활용을 활성화했습니다.
- 가공 횟수 범위, 다중 결과 수량, 재료 비율, 모루 5회 패턴, 담금질을 반영했습니다.
- 섬유 8개, 판석 조각 2개, 작은 돌 조각 3개, 돌/철 화살 25개를 배수 제작에도 적용합니다.
- 가죽 2개+실 2개처럼 결과가 겹치는 조합은 결과 선택창에서 모자 2개 또는 조끼 1개를 선택합니다.
- 머리/몸통/하의/신발 슬롯을 분리하여 제작한 방어구를 함께 장착할 수 있습니다.
- 히든 날카로운 나뭇가지는 제작 가능하며 기존 발견 조건에 따라 레시피 목록에 나타납니다.

## 보류 및 미정 항목

- 취소선인 흡혈·강철·화염·바람·흑요석 제작 경로는 데이터에 보존하고 제작은 비활성화했습니다. 기존 저장 아이템은 계속 읽을 수 있습니다.
- 화염·바람 숫돌 횟수는 문서의 ‘철과 동일’이라는 공통 설명을 적용해 저장했지만, 제작을 활성화하지 않았습니다. 해당 계열 화살은 개별 기재된 10개를 유지했습니다.
- 흑요석 화살촉의 가공 횟수는 0으로 미정 상태를 표시하고, 제작을 차단했습니다.
- ‘강철 흉’은 대응 부위에 맞추어 표시명을 ‘강철 흉갑’으로 정리했습니다. Notion 원문은 바꾸지 않았습니다.
- 레시피에 없는 장비 수치는 만들지 않았습니다. Notion에 기재된 공격력·방어력·가격은 CSV에서 반영하고, 기재되지 않은 값만 기존 미설정값 또는 임시값을 유지합니다. 전용 아이콘은 기존 범주별 스프라이트를 재사용합니다.
- 숙련도 5회 성공 시 레벨 2, 장인급 미해금 등 기존 테스트 설정은 유지합니다.

## 사용법

`Assets/JinHo/Crafting/Scenes/BlacksmithShop.unity`를 열고 Play 합니다.

1. 홈의 **테스트 재료 받기**를 누르면 활성 레시피에 필요한 채집 재료와 연료를 보관함에 종류별 최대 30개까지 보충합니다. 기존 저장을 초기화하지 않습니다.
2. 철 원석 → 용광로 → 달궈진 철 → 모루 상2/하2/중앙1 → 달궈진 긴 철 칼날 → 담금질 → 긴 철 칼날.
3. 나무 원목 → 톱5~6회 → 나무 판자 → 칼6~7회 → 나무 자루.
4. 이끼 슬라임의 점액 2개 → 용광로 → 강력한 접착제.
5. 긴 철 칼날 + 나무 자루 + 강력한 접착제 → 작업대 → 철 검.
6. Tab은 발견한 레시피를 표시하며, 가공 횟수와 결과 수량도 표시합니다. 성공 제작 5회 후 자동 제작이 열립니다.

## 파일과 갱신

- 편집 원본은 `Assets/JinHo/Crafting/Data/Csv/`의 `items.csv`, `recipes.csv`, `recipe_ingredients.csv`, `field_items.csv`, `resource_drops.csv`, `tools.csv`이다. UTF-8 CSV이며 쉼표·따옴표가 든 문장은 표준 CSV 인용 규칙을 쓴다.
- `items.csv`의 자원·제작물·장비·전리품·부산물 가격과 수치, `field_items.csv`의 무게·동화 감소율은 읽기 전용 Notion 표를 따른다. 나머지 가격·드롭 수량은 `source_status`/`price_status`에서 기존값·임시값 여부를 구별한다.
- `items.csv`의 `carryWeightKg`는 전용 필드 아이템이 없는 제작물의 가방 무게에 쓰인다. 현재 값 1kg은 기존 동작을 보존한 임시값이며 `carryWeight_status`로 표시했다. 필드 자원·전리품의 무게는 `field_items.csv`가 우선한다.
- `tools.csv`는 기본 검·도끼·곡괭이의 피해량·사거리·공격 속도·공격 형태를 관리한다. 상점의 도끼·곡괭이 단계와 가격은 `items.csv`의 `toolKind`·`toolTier`·가격 열을 사용한다. 스프라이트, 아이콘, 프리팹 참조는 Unity 에셋에 유지한다.
- `Blacksmith/Import CSV content`를 실행하면 전체 참조와 자료형을 먼저 확인한 뒤 기존 `TestCatalog.asset`, 16개 필드 `ItemData`, 3개 기본 `ToolData`, `ResourceData` 드롭 수량에 적용한다. 기존 GUID·아이템 ID·저장 형식을 유지한다.
- `Blacksmith/Build playable scene and verify`도 동일한 CSV를 읽는다. 씬 생성 명령이므로 열려 있는 씬 작업을 저장한 뒤 실행한다.
- `NotionRecipes.json`은 이전 구조화 스냅샷으로 보관하며 더 이상 가져오기 원본으로 사용하지 않는다. 미기재 가격·주간 빚·업그레이드 가격은 현재 `CampaignRules.asset`의 임시 규칙이다.
- 검증과 출처 범위는 `Docs/Cycles/C030-csv-content.md`를 참고한다.

## 검증

기존 C030 검증 시점에는 격리 Unity 6000.3.11f1에서 CSV 가져오기·컴파일, 202개 아이템·189개 레시피·350개 재료 행·16개 필드 아이템·3개 기본 도구·14개 드롭 행 및 레시피 검사 3,182개가 통과했다. 이번 개정 후에는 205개 아이템·194개 레시피·355개 재료 행의 CSV 가져오기와 활성/비활성 경로 검사가 별도 격리 Unity에서 통과했다. 현재 C# 빌드 오류는 0개다. 실제 제작 입력과 플레이어 빌드는 확인하지 못했다.
