# C021 staggered first-switchback footholds — 2026-09-28

Historical state: the y coordinates below were changed by [C022](C022-corner-foothold-y-order.md).

`FieldMapStructureTest.unity` adds two separate one-way footholds near the first far-right cave switchback. The lower ledge occupies x 100–102, y -17 (top -16); the middle ledge occupies x 104–106, y -16 (top -15). They lead toward the existing x 108–110, y -14 ledge (top -13). Both new ledges use the existing PixelFantasy cave tile as collider-free art and independent Ground `PolygonCollider2D`/`PlatformEffector2D` surfaces. The surrounding wall and forest are unchanged. This makes three offset footholds at different x/y positions without turning their sides into walls.

An isolated Unity 6000.3.11f1 editor saved/reloaded the scene and verified both three-cell art strips, independent one-way colliders and 11 total marked platforms. Play Mode tested jump/landing and S drop on each added ledge with a player-sized physics probe. A separate Play Mode test drove the actual saved player, `PlayerMovement`, roll state and 2D physics for 212 fixed frames: cave ground → lower ledge → middle ledge → original corner ledge, then middle → lower → cave ground. Real roll movement was observed in both the upward and downward portions. Input state was injected into `PlayerInputHandler` because batch-mode `PlayerInput` did not pair a keyboard; this validates gameplay code and collision under simulated controls, not physical keyboard hardware or manual feel. No rendered Game View review or player build was run. The source editor was not reloaded, and no Notion content, runtime script, other scene, commit or push was changed.
