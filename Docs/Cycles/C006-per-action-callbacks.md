# C006 per-action player callbacks

Request (2026-09-26): replace the single dispatch function with a separate callback function for each input action. Preserve C005 input behavior, Input Actions asset, serialized fields/GUID, and consumer-facing properties/consume methods.

PlayerInputHandler now subscribes each cached Player action directly to its method: Move, Sprint, Jump, Interact, Roll, Attack, Inventory, ToolScroll and ToolSlot1/2/3. Move, Sprint, Jump and Attack subscribe to the phases needed for both press/value and release; Interact subscribes to started so the existing Hold interaction still begins quick interaction on press. Scroll remains a PassThrough Axis action from `<Mouse>/scroll/y`. Continuous values remain cached while modal UI blocks the public getters; one-shot inputs are ignored or cleared at UI boundaries. `PlayerInteraction` continues to consume Attack flags from this handler.

OnEnable subscribes, OnDisable unsubscribes, and Start rebinds after PlayerInput has initialized or cloned its action asset. Both subscription and removal are idempotent by `actionsSubscribed`. The runtime PlayerInput notification setting is still InvokeCSharpEvents, so the previous SendMessage notification path is not used. The Input Actions asset, scene, prefabs and Inspector field names were not changed in C006.

Validation: runtime and Editor assembly offline Roslyn compilation passed with zero errors using installed Unity 6000.3.11f1 references. Static checks confirmed 11 action method subscriptions, corresponding unsubscriptions, existing public consumer methods, the original serialized field and absence of Update/global dispatch. Installed source and original `.meta` were hash-verified. Unity asset import and Play Mode behavior remain unverified; the prior Unity validation retry rejection for source/save drift remains unresolved. Manual checks: held Move/Sprint/Jump through modal UI, quick Interact before Hold completion, roll, Attack press/hold/release, inventory toggle, wheel direction and all tool slots.
