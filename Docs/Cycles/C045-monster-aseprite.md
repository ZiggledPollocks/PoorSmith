# C045 MossSlime and VampireBat Aseprite art — 2026-09-29

The existing `MossSlime` and `VampireBat` controllers keep their AI, health, hitboxes, drops and spawn prefab identities. Both base prefabs and both `Spawn_` campaign prefabs now use the user-provided `.aseprite` sprite frames. Their root scales and gameplay settings remain unchanged. The importer pixel density is 20 PPU for slime and 18 PPU for bat, bringing the new first-frame widths close to the previous PNG art at the saved prefab scales. The visible body collider is still fitted once from the new first frame in Play Mode.

The slime tags map as `idle` (frames 0–9), `moving` (10–17), `attack` (18–23), and `damage` (24–28). Idle/moving switch with grounded motion; contact damage plays the attack sequence, then returns to idle/moving. The bat tags map as `flying` (0–3) for resting/flight, `attack` (8–12) for a dive, and `damage` (4–7) for death. Neither source has a `death` tag, so the user chose the new damage sequence for death in both species. The controllers use serialized `Sprite[]` frames; Unity's generated Aseprite `AnimationClip` subassets are present but are not attached to an Animator.

An isolated Unity 6000.3.11f1 copy imported both sources and compiled the controllers. Play Mode confirmed all frame arrays and initial/attack/death sprites on all four prefabs, retained colliders, and field spawning at all affected zones: slime 4/4 and bat 4/4. The Aseprite frame samples were visually inspected in a contact sheet. Actual keyboard combat, the rendered Game View and a player build were not run.
