# C049 shared inventory ledger — 2026-09-29

The field bag and smithy chest/bag still have distinct UI, carrying-capacity and crafting/equipment policies. Their stack mutations now use `Assets/JinHo/Shared/Inventory/InventoryStackLedger.cs`. The ledger accepts adapters for the existing serialized `InventoryItem(ItemData, quantity)` and `Blacksmith.Stack(itemId, quality, count)` types, so scenes, Inspector references, item IDs and version-one save JSON remain unchanged. `InventoryRequirements` continues to aggregate duplicate costs and check recipe batch multiplication.

Field `InventorySystem` routes add, remove, duplicate-cost consumption, snapshot copy, count and weight calculation through the ledger. Weight admission stays a field-bag policy. Smithy `InventoryService` routes stack add, chest/bag/selection transfer, selection return, reorder, fuel consumption and equipped-stack removal through the ledger; crafting station and equipment restrictions stay in that service. Full selection return preflights stack overflow before moving anything. `SmithingItemBridge` checks target count overflow before consuming field ownership, and removes an exported source stack through the ledger only after field admission succeeds. This retains the existing carried-bag/chest transfer destinations during scene travel.

The ledger validates quantity and integer overflow before mutation. Failed duplicate-cost consumption, overweight pickup, stack transfer or selection return leaves original ownership unchanged. There is no new runtime component or serialized field.
