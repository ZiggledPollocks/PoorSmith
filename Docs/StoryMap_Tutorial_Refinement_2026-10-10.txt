요구별 구현·검증
1. 도구 지급
GrantTutorialGatheringTools가 기존 보관함 지급 경로로 town_axe_1과 town_pick_1을 각각 1개 지급한다. 별도의 GrantOnce 키로 중복을 막는다.
정상 Scene 9, 스킵 승인, 실제 저장 후 이어하기 두 번의 수량 보존 통과. 스킵 취소는 지급하지 않는다.
곡괭이는 자동 장착하지 않는다. 기존 나무 검·도끼 장착 완료 조건은 유지했다.

2. 도입부 검과 검은 배경 퇴장
LeavePurchasePresentation에서 두 이미지의 alpha를 같은 값으로 .45초 동안 감소시킨 뒤 함께 정리한다.
실제 coroutine의 단계별 alpha와 CancelPresentation의 잔여 이미지 제거 통과. 구매 데이터는 이미지 표시와 분리했다.

3. SampleScene의 실제 스토리 숲
StoryForestStage prefab 한 개를 SampleScene의 x=5000 별도 루트에 저장했다.
Field의 Forest surface 타일맵·PolygonCollider, 숲 배경 5영역, 원래 Sprite·Collider·ResourceData 참조를 가진 나무 18개를 포함한다.
몬스터와 몬스터 SpawnZone, 플레이어, HUD, 게임 관리자는 복제하지 않았다. 원본 FieldMapStructureTest는 변경하지 않았다.
정상 Scene 2에서 실제 숲과 메인 카메라 사용, 자원 참조, 몬스터 제외 통과.
추가 발견: SampleScene에는 ItemDropSpawner가 없어 복사한 자원에서 드롭이 생성되지 않았다. 기존 Spawner 하나를 숲 루트에 연결한 뒤 실제 나무 타격→드롭을 재검증했다.

4. 동굴 입구
기존 입구 아트·벽을 사용했다. 루트 로컬 x=28의 입구, x=23의 2×3 F 트리거, cameraBounds x=[-48,40], y=[-7,20].
StoryForestCaveGate는 기존 튜토리얼 cave 허용 조건을 검사하고, 허용되면 FieldSceneTravel의 기존 페이드·안전 도착 경로로 필드 동굴 (44,1.5)에 연결한다.
준비한 접근 위치에서 입구 중심·상호작용 영역이 화면 안에 있고 실제 지면 접촉, 필드 동굴 이동, 입력 복원이 되는지 통과했다.
전체 장식 아트가 모든 접근 좌표에서 완전히 보인다고 판정하지 않았다. x=23 검사에서는 오른쪽 장식 끝이 일부 잘린다.

5. Scene 2·3의 발과 나무 검
실제 지형 기준 도착 배치를 사용하고, PoseActor/RestorePose에서 SpriteRenderer.bounds.min.y를 유지한다.
Scene 2의 앉은 자세에서 발이 지면에 있는지 통과. 모든 애니메이션 프레임의 발 정렬을 전수 검사한 것은 아니다.
Scene 3은 실제 wood_sword Sprite를 중앙 상단 x=.43–.57, y=.68–.92에 원본 비율로 표시한다. 정상 실행 캡처로 확인했다.

6. 첫 실내 이동
Scene 4의 첫 두 MoveActor 호출에만 horizontalOnly를 적용했다. 시작 y를 유지하고 목표 x로 이동한다.
준비한 실제 coroutine에서 목표 y가 달라도 매 프레임 y가 일정하고 목표 x에 도달하는지 통과했다.

7. 제작 도구 이름
칼·대패·톱·숫돌·망치의 기존 연결과 버튼·아이콘 배치는 유지했다.
ToolName_0–4에 밝은 크림색, 굵은 글자, 최대 24/최소 19, 작은 짙은 받침과 테두리를 적용했다. 현재 대상 이름도 강조 영역에 포함한다.
실제 제작 화면 및 보조 UITest의 이름 연결·표시 검사를 통과했다.

8. ‘내 말을 따르렴’과 복귀
기존 튜토리얼 대화 UI를 사용한다. 원래 대사, 노출 글자 수, 목표, 강조와 진행 상태를 보존한다.
반복된 잘못된 재료 선택으로 안내가 쌓이지 않음, 공통 Advance의 첫 입력은 문장 완성/다음 입력은 원래 안내 복귀, 목표 보존과 입력 복원 통과.
거치대 안내가 반복되던 원인은 완료 task가 작업실 종료 후에도 남고 안내 복귀 잠금이 늦게 해제되는 것이었다. AutoCloseWorkshop에서 task를 정리하고 Until이 안내 복귀 잠금 해제를 기다리도록 수정했다.
MiniNext의 실제 UI 공통 핸들러로 확인했다. 해당 정지 구간에서 합성 Space가 전달되지 않아 그 구간의 물리 Space 완성→복귀는 미검증이다. 도입부 Space/S 합성 입력은 통과했다.

9. 실제 SampleScene 제작 튜토리얼 배치
수정 전 실제 캡처에서 목표 안내가 ‘재료 보관함’ 제목을, 하단 미니 대화가 ‘시작하기’와 작업 설명을 가렸다.
기존 제작 UI는 이동하거나 축소하지 않았다. StoryTutorialView만 현재 대상, 이름, 설명의 실제 표시 영역을 기준으로 후보 위치를 고른다.
사용자 허용에 따라 제작 중 미니 대화는 화면 비율 .36×.16으로 줄였다. 필드 미니 대화의 기존 .46×.19는 유지한다.
축소 크기를 문장 분할 전에 적용해 긴 대사가 잘리지 않도록 했다. 제작 목표 패널은 .34×.08로 빈 영역을 선택한다.
현재 쓰지 않는 비활성 도구는 가려질 수 있다. 필수 대상은 강한 우선순위로 보호하고 단계가 바뀔 때만 .16초 동안 이동한다.
실제 새 게임 경로의 도구 선택, 재료 선택, 레시피, 칼·숫돌, 조립 화면을 캡처하고 필수 대상 겹침과 본문 크기를 검사했다. 최종 실행 결과와 캡처 경로는 별도 증거 JSON에 기록한다.

10. 보존과 문서
백업과 SampleScene의 원래 423개 YAML 문서를 비교했다. 422개는 그대로이고 SceneRoots 참조 하나/PrefabInstance 하나만 추가했다. 기존 문서 삭제는 없다.
FieldMapStructureTest 바이트 불변, 새 프리팹의 152개 local ID 유일, 독립 검증 전후 원본 변경 [] 및 일반 저장 해시 동일.
기존 옵시디언 인수인계 문서와 변경 로그에 변경·사용법·검증을 짧게 반영했다.

실제 실행 범위와 방법
새 게임 → 도입부 구매 → SampleScene 숲 → 대장간 → 톱·칼·숫돌·작업대 제작 → 나무 검·도끼 장착 → 채집 필드 → 나무 채집·사슴 드롭 → F 석상 → F 귀환 → 납품 → 수면 → 2일 차.
제작 UI는 실제 pointer/버튼 handler, 제스처와 타이밍을 사용했다. 마을 상호작용, 거치대, 납품, 침대는 실제 handler를 직접 호출하는 자동 검사이므로 모든 구간을 사람이 마우스·키로 완주한 것과 구분한다.
필드는 InputSystem의 방향·숫자·좌클릭·F 입력으로 나무 3개 이상 소진, 사슴 공격·가죽 획득·석상·귀환을 확인했다.
동화율이 0이면 20으로 준비해 제물 검사만 가능하게 하는 테스트 조건이 있었다. 이번 검사에서 7일간의 활동을 정상 플레이한 것은 아니다.
스킵, 실내 자동 이동, 입구 접근, Scene 9 저장 후 이어하기는 격리 준비 상태를 사용한 분기 검사다.
캡처는 실제 월드 카메라+전체 Canvas를 렌더했다. 실제 검증 Game View 비율과 1920×1080/1280×720/1600×1000 출력을 구분한다. 캡처 중 일부는 전체 문장만 잠시 드러내고 복원했다.
